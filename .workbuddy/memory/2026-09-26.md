## 为 ImageViewer 增加右键菜单与圆环图形

- 新增 `RingShape`（同心圆环带）：`Center` + `InnerRadius` + `OuterRadius` + `Thickness`。
  9 个控制点（圆心 1 / 外圆 4 / 内圆 4）；填充用双圆路径 + `FillMode.Alternate` 自动镂空内孔。
  内半径取 0 时退化为实心圆；内外半径互相 clamp，环带厚度不小于 `MinGap`(1)。
- `InteractionMode` 增加 `DrawRing = 5`：按下定圆心，拖动定外半径，内半径默认取外半径一半。
- ImageViewer 内置右键菜单，通过 `ViewerContextMenu` 属性暴露给外部扩展：
  保存图像 / 保存视图截图 / 自适应图像 / 显示辅助十字线。

### 右键交互的关键设计（易错）

- 右键**单击**弹菜单，右键**拖动**仍是平移 —— 用 `_rightDragged` 标志 + 4px 阈值区分。
- **没有**使用控件的 `ContextMenuStrip` 属性（它会在右键 MouseUp 时无条件弹出）。
  改为自己持有一个 `ContextMenuStrip` 实例，在 `OnMouseUp` 判断后手动 `Show()`。
- 否则右键平移会被菜单打断，两者无法共存。

## 增加右下角 HUD（鼠标坐标 + 像素值）

- `RenderOptions` 新增 `ShowHud` / `HudBackColor` / `HudForeColor` / `HudBorderColor`（默认开启）
- `ImageViewer.ShowHud` 属性转发；`DrawHud()` 在 OnPaint 末尾绘制，右下角，左侧带色块预览
- 显示规则：灰度图 → `Gray: 173`；彩色图 → `Color: (201, 96, 44)`；越界 → `--`
- 灰度判定 `IsGrayImage()`：`Format16bppGrayScale`，或调色板全为灰阶的 `Format8bppIndexed`

  事件共用，避免每次重绘都调 `GetPixel`；`SetImage` 时清空缓存

## 修复：画圆环点击无反应（BUG）

- 根因：`OnMouseDown` 中判断「是否进入绘制」的 switch 只登记了
  `DrawCircle` / `DrawRectangle` / `DrawRotatedRect`，**漏了 `DrawRing`**。
  于是圆环模式下鼠标按下走 default 分支 → `StartSelectOrDrag`，永远不开始绘制。
  枚举值、`UpdateDrawing` 预览、`UpdateCursor` 三处都补了，唯独漏了分发这一处。
- 修复：抽出静态 `IsDrawingMode(InteractionMode)` 集中判断，
  `OnMouseDown` 与 `UpdateCursor` 都改用它。以后新增图形类型只需登记一处，不会再漏。
- 教训：给枚举新增成员时，必须全局搜索该枚举的**所有** switch / 分支点逐个补上；
  更稳妥的做法是把散落的分支收敛成单一判断函数。

## 修复：Demo 右侧数据不随图形拖拽更新

- 根因 1：`MainForm.RefreshShapeList()` 为防闪烁做了「数量没变就不重建列表」的优化，
  但列表项文本来自 `shape.ToString()`（几何参数）——不重建就永远不刷新，
  于是拖拽图形时右侧数值纹丝不动。改为每次 `ShapesChanged` 都整表重建
  （`BeginUpdate`/`EndUpdate` 抑制闪烁），重建前后保持 `SelectedIndex`。
  图形数通常个位数，60Hz 重建开销可忽略。
- 根因 2：状态栏 `_lblSelection` 用 `Text.StartsWith("新建："/"已导出"/"OpenCV")`
  判断是否覆盖几何文本。画完一个图形后文本以「新建：」开头，之后拖拽永远不会更新。
  改为显式状态标志 `_transientMessage`：有选中图形时始终显示其几何并清除标志；
  临时提示（新建 / 导出 / OpenCV 往返）统一走 `SetTransientMessage()`，
  下一次几何更新自动顶掉。
- 教训：**用字符串前缀判断状态是脆弱的**，应改用显式布尔标志。
  另外「为性能跳过刷新」的优化，必须确认被跳过的内容确实不需要刷新。

## 性能优化：8192x4000 8bpp 灰度图下鼠标移动卡顿

测试图 `1_2.bmp`：8192x4000、8bpp 灰度、3276 万像素、31MB。做了三层优化：

1. **静态内容缓存层** `_imageLayer`（背景 + 图像 + 像素网格）
   - 只在图像 / 缩放 / 平移 / 控件尺寸变化时重建（统一走 `InvalidateView()`）
   - 鼠标移动、拖拽图形直接复用 → 直接解决「鼠标一动就卡」
   - `OnPaintBackground` 改为空实现（背景已在缓存层里，省一次全屏填充）
   - 新增 public `InvalidateImageLayer()`：直接改 `Options` 配色后必须调用它，
     只调 `Invalidate()` 不会重建缓存
2. **索引色转 24bpp** `ToDisplayBitmap()`
   - GDI+ 缩放绘制 8bpp 索引位图极慢（每像素都要查调色板）
   - SetImage 时自动转 24bpp；**灰度判定 `IsGrayImage` 必须在转换前做**并存到
     `_imageIsGray`，否则转换后一律 24bpp，HUD 会误显示 Color 而不是 Gray
   - 所有权变复杂：新增 `_ownsDisplayImage`（产生副本时控件必定拥有该副本）
3. **超大图缩略图** `_scaledImage`
   - Zoom<1 且图像 > 800 万像素时，改用按当前 zoom 预生成的缩略图整图 1:1 贴
   - 只在图像更换或 **zoom 变化**时重建；平移时 zoom 不变 → 直接复用（关键）
   - 注意：`InvalidateView()` 里**不能**设 `_scaledImageDirty`，
     否则平移每帧都重建缩略图，优化完全失效
   - 另：源区域 > 800 万像素时 `HighQualityBicubic` 自动降级 `HighQualityBilinear`

## 性能优化（第二轮）：滚轮缩放卡顿 → 图像金字塔

上一轮「按当前 zoom 生成整幅缩略图」的方案有致命缺陷：
**每滚一格 zoom 就要重建整幅缩略图**，等于每帧对 3276 万像素做一次全图下采样 → 缩放卡。

改为**图像金字塔（mipmap）**：
- `_pyramid`：逐级 1/2 下采样，第 i 级 scale = 1/2^(i+1)，最粗到 32px 为止
- 逐级生成（下一级由上一级而来），总代价 ≈ 原图的 1/3，**只在换图时生成一次**
- 绘制时按 zoom 选层：`SelectPyramidLevel` 从最粗往回找第一个 `scale >= zoom` 的层，
  找不到就退回原图（zoom 接近 1 时）
- 缩放只是「换一层」，不再重新采样整图 → 滚轮连续缩放流畅
- 选到层后**仍然只渲染可见区域**：源（层内可见部分）与目标（屏幕）都很小，双重优化

判据也修正了：从「整图像素数」改为「**可见源区域**像素数 > 200 万才用金字塔」——
这才真正反映单帧的采样量，原判据在 zoom 接近 1 时会误判。

**关键教训：缓存的失效条件必须避开高频操作。**
上一轮缩略图的失效条件是「zoom 变化」，而缩放本身正是高频操作，缓存等于白建；
金字塔的失效条件只有「换图」（低频），缓存才真正生效。

附带：Demo 打开图片改为 `File.ReadAllBytes` + `MemoryStream` 解码 ——
既避免 `new Bitmap(path)` 长期锁文件句柄，又省掉一次 8192x4000 全尺寸拷贝
（原做法 new Bitmap(w,h) 是 32bppArgb，那一次就要 131MB）。

## 新建 VisionPlatform 工业视觉软件（C++/OpenCV 算法 + C# WinForms 界面）

新增 `VisionPlatform.sln`，三个项目：
- `src/VisionAlgo.Native`（C++ DLL，OpenCV 4.5.5）：预处理/Blob/清晰度/圆拟合/直线拟合/模板匹配
- `src/VisionPlatform`（C# WinForms 4.8，x64）：登录/加载/主框架 + 相机·算法·通讯·配方四面板
- 复用 `src/VisionSystem.Controls`（算法面板用它显示灰度图与图形叠加）

架构要点：
- 唯一 P/Invoke 边界 `Native/VisionAlgo.cs`；界面不碰算法，算法不认识界面
- C 端 `extern "C" __stdcall` 导出，`VA_Image{data,w,h,channels,stride}` 描述 cv::Mat 布局，
  C# 侧 `LockBits` 后**零拷贝**传入；输出缓冲区一律 C# 分配（不跨模块分配/释放）
- 相机抽象 `ICamera` + `SimCamera`（无硬件可跑通全流程）+ `HikCamera`（占位）+ `CameraManager`
- 通讯：TCP 客户端/服务端 + **自实现** Modbus TCP（0x03/0x06/0x10，无第三方依赖）
- 配方 JSON 用 `DataContractJsonSerializer`（零 NuGet）

### 踩坑清单（重要，都会复现）

1. **vcxproj 的 `<WarningLevel>` 必须写 `Level3`**，写 `3` 会报「元素具有无效值"3"」(MSB6011)
2. **MSB6001：CL.exe 命令行开关无效 … 关键字 "https_proxy"/"HTTPS_PROXY"**
   —— 宿主 shell 注入了大小写不同的代理变量，MSBuild 用不区分大小写字典构建子进程环境时冲突。
   解决：bat 里 `set http_proxy=` 等全部清空后再调 MSBuild
3. **bat 必须纯 ASCII**（我又踩了一次！中文注释在 GBK 下乱码，把命令解析搞坏，
   报 `'sionAlgo.Native' 不是内部或外部命令`）
4. **C++ 源文件含中文注释要加 `/utf-8`**（vcxproj 的 `AdditionalOptions`），
   否则 GBK 解析会产生 C4819，并**破坏后续函数签名**（C2447「{ 缺少函数标题」），
   表现为一堆「找不到标识符 ToMat」的连锁错误
5. 命名空间 `VisionPlatform.Recipe` 与类 `Recipe` 同名 → UI 层用
   `using RecipeModel = VisionPlatform.Recipe.Recipe;` 别名规避
6. `OpResult<T>` 只有单参 `Fail(string)`；带 params 的 `Fail` 在基类且返回 `OpResult`，
   在返回 `OpResult<T>` 的方法里调用会类型不匹配 → 用 `string.Format` 包一层
7. x64 链路：C++ 是 x64，C# 主程序必须 `<PlatformTarget>x64</PlatformTarget>`；
   sln 用 `Debug|x64`，Controls/Platform 项目映射到 `|Any CPU`
