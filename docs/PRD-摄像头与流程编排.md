## 2. 产品目标

### 需求 1：本机摄像头实时显示

- **问题**：现场调试时，用户可能既没有海康工业相机，也不方便用合成图像调参；笔记本内置摄像头 / 普通 USB 摄像头随手可得，但系统当前无法枚举、打开它们。
- **目标用户场景**：
  - 现场工程师在无工业相机环境下，用本机摄像头做算法取图与联调预览。
  - 售前/演示场景，快速展示"实时采集 → 检测"的完整链路，无需携带工业相机。
- **目标**：
  - **G1**：能枚举出本机（USB / 内置）摄像头，并在相机管理界面**打开**。
  - **G2**：打开后可**连续采集并实时显示**（预览流畅、可停止）。
  - **G3**：无任何真实硬件时**合理降级**到现有 SimCamera，界面不报错、不阻断流程。

### 需求 2：算法页面改为模块拖拽式流程编排

- **问题**：当前算法页是"一页固定参数"，只能跑形状匹配一条固定链路，无法表达"取图 → 若干算法模块 → 结果输出"的可配置流程，也无法与主界面显示窗口 / 相机建立绑定关系。
- **目标用户场景**：
  - 工程师参考 VisionMaster 的操作习惯，用**拖拽 + 连线**方式搭建处理流程。
  - 同一台设备配置**多条流程**（如"定位流程""检测流程"），分别绑定不同相机与不同显示窗口。
- **目标**：
  - **G1**：提供"工具箱 + 画布 + 参数面板 + 流程列表"的编排界面，模块可拖入画布、移动、连线。
  - **G2**：支持多流程的新增 / 重命名 / 删除 / 切换。
  - **G3**：每个流程可绑定**主界面显示窗口（视图序号）**与**相机**，且流程定义与绑定关系**持久化**、二次打开即恢复。

## 3. 用户故事

### 3.1 需求 1（本机摄像头）

**US-CAM-1**：作为现场工程师，我想要在相机管理里看到本机摄像头列表，以便在没有工业相机时也能选一个可用图像源。

- **验收标准**
  - Given 电脑接有至少一个本机摄像头，When 打开"相机管理"并点"刷新列表"，Then 列表中同时出现本机摄像头（与模拟相机、可用时的海康相机并列），且能区分来源。
  - Given 电脑没有任何摄像头，When 刷新列表，Then 仍显示"模拟相机"作为兜底，且不弹错误框。

**US-CAM-2**：作为现场工程师，我想要打开本机摄像头并开始采集，以便实时看到画面。

- **验收标准**
  - Given 列表已选中某本机摄像头，When 点"打开"→"开始采集"，Then 右侧预览区连续刷新画面（肉眼判定流畅），可"停止采集"后再"开始采集"。
  - Given 摄像头被其它程序独占或被拔除，When 打开/采集，Then 在界面给出明确失败原因，不崩溃。

**US-CAM-3**：作为现场工程师，我想要抓取单帧本机图像，以便做离线分析或喂给算法页。

- **验收标准**
  - Given 本机摄像头已打开，When 点"抓一帧"，Then 右侧预览显示该帧静态图。

**US-CAM-4**：作为算法工程师，我想要在算法/流程页选用本机摄像头作为图像源，以便流程能实时取图。

- **验收标准**
  - Given 本机摄像头已在相机管理中打开，When 在流程中绑定该相机，Then 运行流程时可从该相机取到图像。

### 3.2 需求 2（流程编排）

**US-FLOW-1**：作为算法工程师，我想要在画布上拖入模块并连线，以便自由搭建处理流程。

- **验收标准**
  - Given 打开编排界面，When 从左侧工具箱拖拽某模块（如"形状匹配"）到画布，Then 画布生成一个文本节点并落于鼠标位置，节点可再次拖动改变位置。
  - Given 画布上有两个模块，When 从一个节点拖出连线到另一个节点，Then 两节点间出现一条有向连线。

**US-FLOW-2**：作为算法工程师，我想要管理多条流程，以便为不同工位配置不同链路。

- **验收标准**
  - Given 编排界面，When 点"新建流程"，Then 流程列表新增一项且自动切换为当前流程（画布可独立编辑）。
  - Given 存在多条流程，When 重命名 / 删除 / 切换，Then 列表与画布同步更新；删除当前流程时给出确认并切换到剩余流程（若删空则自动新建一条空流程）。

**US-FLOW-3**：作为算法工程师，我想要把流程绑定到主界面某个显示窗口和某个相机，以便流程结果直接显示到指定窗口。

- **验收标准**
  - Given 主界面为 2x2 布局，When 在某流程的绑定设置中选择"视图 3"与某相机，Then 该流程运行时结果输出到视图 3，且使用该相机取图。
  - Given 已设置绑定，When 关闭软件后重新打开，Then 流程定义、节点位置、连线、绑定关系**完整恢复**。

**US-FLOW-4**：作为算法工程师，我想要选中节点后编辑其参数，以便复用现有形状匹配能力。

- **验收标准**
  - Given 画布中选中"形状匹配"节点，When 在右侧参数面板修改参数（如最小得分），Then 参数随节点保存并在流程运行时生效。
  - Given 未选中节点，Then 参数面板显示为空态提示。

**US-FLOW-5**：作为算法工程师，我想要按连线顺序运行流程并看到结果，以便验证编排是否正确。

- **验收标准**
  - Given 流程"图像源 → 形状匹配 → 结果输出"已连线并绑定相机/视图，When 点"运行"，Then 按顺序执行各节点，并将最终结果叠加显示到绑定视图。
  - Given 流程存在未连接节点或成环，When 点"运行"，Then 给出可读提示且不执行（P2）。

## 4. 需求池

优先级说明：**P0** 必须（本增量核心，缺失则不可用）；**P1** 应该（显著提升可用性）；**P2** 可选（增强项）。

### 4.1 需求 1 —— 本机摄像头

| ID | 需求描述 | 优先级 | 验收要点 |
| --- | --- | --- | --- |
| FR-CAM-01 | 在 `CameraManager.Enumerate()` 中枚举本机摄像头（USB / 内置），生成 `CameraInfo`（Id 采用 `USB-n` 前缀，Name 形如"本机摄像头 n"） | P0 | 刷新列表能列出本机摄像头；无摄像头时不报错，仅保留 SimCamera |
| FR-CAM-02 | 新增 `ICamera` 实现（如 `LocalCamera`），`CameraManager.CreateById()` 增加 `USB` 前缀分发；实现 Open/Close | P0 | 打开成功返回可用实例；打开失败（被占用/拔除）返回明确错误文本 |
| FR-CAM-03 | 实现 `StartGrab/StopGrab` 连续采集，采集帧经 `FrameReceived` 事件回调，`UI/CameraForm` 右侧 ImageViewer **实时显示** | P0 | 采集期间画面连续刷新；停止后线程安全退出；可重复启停 |
| FR-CAM-04 | 实现 `GrabOne(timeoutMs)` 单帧抓取（接口契约要求，算法页"从相机取帧"依赖） | P0 | 已打开时可取到一帧；超时/失败返回失败结果 |
| FR-CAM-05 | 采集线程异常（掉线、读帧失败）经 `ErrorOccurred` 上报并写入日志，界面给出提示且不崩溃 | P1 | 拔除设备后采集自动结束并提示；日志有记录 |
| FR-CAM-06 | 无真实硬件（无海康、无本机摄像头）时，无缝降级到 `SimCamera`，主流程（循环运行 / 同步采集）保持可用 | P0 | 断网/无硬件环境下 `CanRunLoop` 仍可通过（因 SimCamera 打开） |
| FR-CAM-07 | 本机摄像头可配置分辨率 / 采集后端（DShow / MSMF）（可后置） | P2 | 支持在界面或配置中选择，默认自动 |

**实现手段（约束项）**：本机摄像头采集**不引入任何新依赖**，统一"经 `VisionAlgo.Native` 的 C++ 层用 OpenCV `VideoCapture` 封装后由 C# P/Invoke 调用"（OpenCV 运行时 `opencv_world455.dll` 已在输出目录）。C# 侧仅新增 `ICamera` 适配器，控件库仍保持零第三方依赖。

### 4.2 需求 2 —— 流程编排

| ID | 需求描述 | 优先级 | 验收要点 |
| --- | --- | --- | --- |
| FR-FLOW-01 | 多流程管理：新增 / 重命名 / 删除 / 切换；多流程各自独立的节点与连线 | P0 | 切换流程画布内容随之切换；删空自动补一条空流程 |
| FR-FLOW-02 | 左侧**工具箱**列出算法模块（**文字块，不需要图标**）：图像源、预处理、形状匹配、Blob、清晰度、圆/直线拟合、结果输出等 | P0 | 模块可读、可拖拽；列表来自统一模块定义 |
| FR-FLOW-03 | 从工具箱**拖拽**模块进入画布，生成节点 | P0 | 节点落点=释放位置；同一模块可重复拖入多个 |
| FR-FLOW-04 | 画布节点**移动**（鼠标拖动改变位置） | P0 | 拖动流畅，位置随流程保存 |
| FR-FLOW-05 | 节点间**连线**表示执行顺序（有向） | P0 | 可建立/删除连线；连线入出口明确 |
| FR-FLOW-06 | 每个流程绑定**一个主界面显示窗口**（视图序号，1..N，N 由当前布局决定） | P0 | 绑定项可选当前布局下的视图；持久化 |
| FR-FLOW-07 | 每个流程绑定**一个相机**（可复用在相机管理里"已打开"的相机） | P0 | 绑定项列出已打开相机；持久化 |
| FR-FLOW-08 | 流程定义（流程列表、节点、位置、连线、参数、窗口/相机绑定、当前流程）持久化到 `appconfig.json`，作为新增配置段 | P0 | 重启后完整恢复；旧配置无该段时按默认补齐不报错 |
| FR-FLOW-09 | **节点参数面板**：选中节点后在右侧编辑参数；第一阶段先接**形状匹配**节点参数 | P1 | 参数修改即生效并随节点保存；未选中显示空态 |
| FR-FLOW-10 | **流程执行**：按连线顺序跑一遍（取图 → 依次执行模块 → 结果输出到绑定视图） | P1 | 运行后绑定视图显示结果；执行耗时/结论可见 |
| FR-FLOW-11 | 工具箱拖拽交互体验：拖影（ghost）、吸附对齐、框选、删除节点/连线 | P1 | 拖拽有视觉反馈；可多选与删除 |
| FR-FLOW-12 | 模块间**数据流校验**：未连线节点、成环、无输入源等给出提示 | P2 | 运行前校验并列出问题，不执行非法流程 |
| FR-FLOW-13 | 运行**日志**（每节点耗时、成功/失败） | P2 | 编排界面或主日志区可见 |
| FR-FLOW-14 | 流程**导入 / 导出**（文件交换，便于复用与备份） | P2 | 导出的流程可在另一环境导入 |
| FR-FLOW-15 | 接入**更多算法模块**（预处理 / Blob / 清晰度 / 拟合等映射到现有原生接口） | P2 | 新增模块可在流程中拖拽执行 |

### 4.3 数据模型（建议，供架构阶段细化）

- `Flow`：`Id`、`Name`、`CameraId`（可空）、`ViewIndex`（1..N）、`Nodes`、`Edges`
- `FlowNode`：`Id`、`ModuleType`（枚举/字符串）、`Name`、`X`、`Y`、`Params`（键值字典）
- `FlowEdge`：`FromNodeId`、`ToNodeId`
- 配置新增段：`AppConfig.Flows`（含 `List<Flow> Flows`、`ActiveFlowId`）；保留现有 `Ui.ViewBindings`（主界面视图↔相机）不动，流程绑定为**新增维度**。

要点：
- **工具箱**：纯文字块列表（不需要图标），拖拽源。
- **画布**：自研 GDI+ 绘制节点（矩形 + 文本）与有向连线；支持拖入、移动、连线、框选、删除。

### 5.3 与主界面的关系

- 主界面 `MainForm` 维持现有"视图 header 内相机绑定下拉框 + `ViewBindings` 持久化"不变。
- 新增：流程可指定"结果输出到视图 N"，与主界面视图序号一一对应（复用 `ShowFrame(viewIndex, cameraName, frame)`）。
- 视图序号 N 的有效范围由当前布局决定（1 / 2 / 4 / 6 / 9）。

## 6. 明确不做的事（Out of Scope）

1. **海康 MVS SDK 真实接入**：`HikCamera` 维持占位实现，本增量不改其 TODO 分支。
2. **流程调试能力**：断点、单步、逐节点暂停、变量监视等不做。
3. **深度学习 / 训练类模块**：不做，仅复用现有传统算法接口。
4. **第三方流程图控件 / 图标体系**：不引入控件库，不做图标资源。
5. **多流程并发同时运行**：同一时刻仅运行一个流程。
6. **云端 / 远程流程分发、配方与流程的复杂联动**：不在本次范围。
7. **撤销 / 重做（Undo/Redo）**、节点自动布局算法：不做（可作为后续增强）。
8. **本机摄像头的音视频编码、录像、RTSP 推拉流**：不做，仅取帧显示。

## 8. 风险与依赖

| # | 风险 / 依赖 | 影响 | 应对建议 |
| --- | --- | --- | --- |
| R1 | **部分机器无本机摄像头**（台式机常见） | 需求 1 无法现场验证 | 保留 SimCamera 兜底（FR-CAM-06）；文档明确"无硬件可用模拟相机" |
| R2 | **OpenCV videoio 后端差异**（DShow / MSMF 行为、占用冲突、分辨率协商不同） | 个别设备打不开或卡顿 | 先探测可用后端并回退；打开失败给出明确错误；异常经 `ErrorOccurred` 上报 |
| R3 | **预编译 `opencv_world455` 是否含 videoio 模块 / 对应后端** | 原生相机接口可能无法编译链接 | 架构阶段先验证 `cv::VideoCapture` 可用；否则调整 OpenCV 预编译包（**仍不引入新依赖**） |
| R4 | **帧格式与性能**：BGR/BGRA→Bitmap 转换、1280x720@30fps 的拷贝开销与 UI 线程切换 | 预览卡顿、内存增长 | 采集线程独立、`BeginInvoke` 切 UI、及时 `Dispose` 旧帧；必要时降分辨率/帧率 |
| R5 | **自研拖拽画布成本**：命中测试、连线路由、框选、重绘性能 | 工期与体验风险 | 分步交付：P0 先"拖入+移动+连线"，P1 再补拖影/框选/删除 |
| R6 | **线程安全**：`CameraManager` 单例与多流程取图并发 | 竞态、句柄泄漏 | 沿用现有 `lock` 约定；流程运行串行化，共享相机取图加锁 |
| R7 | **配置兼容**：新增 `Flows` 段导致旧 `appconfig.json` 反序列化异常 | 启动失败 | 沿用 `ConfigStore.Load()` 的"逐段补齐"模式，缺失即默认值 |
| R8 | **依赖既有能力**：形状匹配依赖非托管 `VisionAlgo.Native.dll` 与 `opencv_world455.dll` 就位 | 流程运行失败 | 沿用 `EnsureAlgo()` 的就位检查与提示文案 |
| R9 | **约束遵守**：控件库零第三方依赖、不得引入 WPF / NuGet 流程图控件 | 破坏架构一致性 | 画布与相机适配器全部自研；相机能力走原生库 P/Invoke |
