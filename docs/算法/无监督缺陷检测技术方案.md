# 无监督缺陷检测技术方案（划痕、缺失、脏污、纹理异常）

> 文档目标：为工业视觉平台选择无监督/自监督异常检测模型、训练口径、部署与推理加速方案提供依据。
> 资料口径：优先采用论文原文与商业软件官方资料；厂商未公开内部算法的部分不做推断。
> 整理日期：2026-11-23。

## 1. 结论先行

1. **不要用一个模型包打所有缺陷。** 划痕/脏污属于局部表面异常，缺失/装配错误属于逻辑或全局结构异常。前者适合 PatchCore、PaDiM、DRAEM、EfficientAD 局部分支；后者必须加入全局上下文分支（EfficientAD 的 AE 分支、MVTec Global Context AD）或专门的规则/模板比对 [P9][P12][C2]。
2. **只有 OK 图冷启动，首选 PaDiM / PatchCore；要求毫秒级且兼顾缺失，首选 EfficientAD。** PatchCore 精度上限高但内存库与 kNN 检索成本大；EfficientAD 论文报告约 2 ms 延迟、600 张/秒吞吐，并有专门检测逻辑异常的自编码器分支 [P7][P9][P12]。
3. **划痕类缺陷先解决成像，再谈模型。** 极细划痕在降采样、大 stride、反光过曝后已经丢失，任何无监督算法都补不回来。暗场/低角度/多角度光照、线扫 LumiTrax 等成像方案往往比换模型更关键 [C5]。
4. **重构/扩散类不是在线首选项。** AE/GAN/diffusion 容易把缺陷“重构回来”造成漏检，且多步采样延迟大；适合离线复检或对可解释热图要求高的场景 [P2][P18]。
5. **商用软件的可核实事实**：Cognex ViDi Red Analyze 有仅学习良品的无监督模式；MVTec HALCON 自 19.11 提供 anomaly detection，并有面向缺失/位置错误的 Global Context AD；LandingLens Anomaly Detection 只用 Normal 图训练、逐像素输出异常分 [C1][C2][C3]。这些产品内部是否使用 PatchCore/师生网络等具体算法，官方未公开，不应推断。

## 2. 适用范围与数据口径

### 2.1 缺陷分类

| 类型 | 例子 | 信号特点 | 是否适合纯局部 patch 方法 |
|---|---|---|---|
| 局部表面异常 | 划痕、脏污、纹理断裂、压痕 | 局部 patch 与正常分布偏离 | 适合 |
| 局部缺失 | 涂层缺口、字符缺笔、局部胶断 | 局部纹理/结构缺失，通常可定位 | 多数适合，需足够感受野 |
| 全局/逻辑异常 | 零件漏装、顺序错、数量错、位置错 | 每个局部都正常，组合非法 | **不适合**，需全局分支/规则 |

### 2.2 训练数据口径

- **仅 OK 样本**：严格意义的无监督。代表：PaDiM、PatchCore、FastFlow、EfficientAD、GANomaly。
- **OK + 合成异常**：自监督。代表：CutPaste、DRAEM；异常由贴片、Perlin 噪声、纹理填充等方式合成。
- **OK + 少量真实异常仅用于阈值/验证**：工程上常见，严格说是半监督调参；不参与训练时可仍称“无监督训练”。LandingLens 官方建议 Development 集保留 10+ 张 Abnormal 用于阈值调优 [C3]。

### 2.3 数据集与真实产线差异

- MVTec AD：15 类、5354 张高分辨率图、73 种缺陷、1888 个像素级标注；受控光照、离散单件、姿态较规整 [P1][D1]。其 99%+ AUROC **不能外推**到反光、透明、线扫连续幅面。
- MVTec 系列数据集采用 CC BY-NC-SA 许可，**不能直接用于商业模型训练**；商业项目需单独授权或自建数据集 [D1][D2][D3]。
- MVTec AD 2：8 个场景、8000+ 图，加入透明/重叠、暗场/背光、极小缺陷与光照变化；SOTA 平均 AU-PRO 仍低于 60% [P14][D2]。
- MVTec LOCO AD：3644 图、5 类，显式引入缺失与逻辑约束异常 [P15][D3]。
- KolektorSDD / DAGM：训练集含缺陷样本，属于弱/半监督口径；DAGM 为合成纹理，98%+ 成绩不代表真实产线 [P16][P17]。

> **置信度说明**：本文的“划痕/缺失区分策略”基于论文数据集与厂商公开资料，属于中等置信度；最终阈值与模型必须通过本产线真实 OK 样本、真实缺陷样本与连续生产验证确认。

## 3. 方法谱系与适用性

| 方法族 | 代表 | 训练口径 | 优点 | 主要风险 | 适用缺陷 |
|---|---|---|---|---|---|
| 模板差分 / Variation Model | HALCON variation model、金样比对 | 仅 OK | 直观、可解释、CPU 可跑 | 位移/姿态/光照敏感 | 高对齐场景的缺失、字符缺笔 |
| 统计纹理 / 频域 | Gabor、LBP、频带能量 | 仅 OK | 轻量 | 无语义结构理解 | 脏污、纹理异常 |
| 低维重构 | PCA、AE、VAE | 仅 OK | 无需异常标注 | 缺陷被重构导致漏检 | 弱纹理异常，不推荐单独用 |
| 特征嵌入 + 内存库 | PaDiM、PatchCore、CFA | 仅 OK | 精度高、可定位、冷启动快 | 记忆库大、kNN 慢；逻辑异常盲区 | **划痕、脏污、局部纹理首选** |
| 正则化流 | FastFlow | 仅 OK | 端到端定位、推理较快 | 对域偏移敏感 | 局部异常 |
| 师生 | Uninformed Students、EfficientAD | 仅 OK | 边缘实时、可加全局分支 | 需要教师质量与蒸馏稳定 | **实时首选，兼顾逻辑异常** |
| 自监督合成异常 | CutPaste、DRAEM | OK + 合成异常 | 无需真实缺陷标注，输出热图 | 合成与真实缺陷域差距 | 划痕、脏污；缺失需覆盖形态 |
| 生成式 | GANomaly、DDAD | 仅 OK | 可生成“无缺陷参考” | 训练不稳定、慢、可能脑补缺失 | 离线复检 |

### 3.1 划痕怎么选

- **纹理背景上的细划痕**：DRAEM / PatchCore；配合暗场或低角度光照。
- **反光金属表面划痕**：先解决光照（多角度、偏振、线扫 LumiTrax），再做 EfficientAD 或 PatchCore。
- **极细且深度未知的划痕**：2D 明暗场/光度立体通常比纯 RGB 无监督更稳；3D 深度只给相对置信度，见 3D 文档。

### 3.2 缺失怎么选

- **局部缺失**（涂层缺一小块、字符缺笔）：可用 PatchCore/PaDiM，但 ROI 与 patch 感受野必须覆盖缺失尺度。
- **整件漏装/顺序错/数量错**：EfficientAD 全局 AE 分支或 MVTec Global Context AD；规则/模板计数作为兜底。
- **不要只靠局部 kNN 分数**：每个 patch 都正常时，局部记忆库不会报警 [P12][P15]。

## 4. 模型选择决策表

| 场景条件 | 首选 | 备选 | 不建议 | 依据 |
|---|---|---|---|---|
| OK < 20 张、单品类、纹理强、划痕/脏污 | PaDiM + 统计纹理基线 | PatchCore few-shot | diffusion、从零训练 GAN | [P7][P9] |
| 只有 OK、多 SKU、划痕为主 | PatchCore，每 SKU 独立记忆库/PCA | CFA 目标域适配 | 一个全局模型配统一阈值 | [P9][P10] |
| 缺件/装配错误/顺序错 | EfficientAD | 商业 Global Context AD | PatchCore/PaDiM 单独使用 | [P12][C2] |
| 纹理强、小划痕、要像素热图 | DRAEM 或 PatchCore | CutPaste、FastFlow | 纯模板差分 | [P8][P9][P6][P11] |
| 反光/透明/线扫连续幅面 | 先改成像，再 EfficientAD/DRAEM | PatchCore | 直接套自然 RGB 预训练模型 | [C5][P10] |
| 延迟 < 10 ms、边缘 CPU/GPU | EfficientAD | FastFlow、PaDiM | 全量 PatchCore kNN、diffusion | [P12][P11] |
| 精度优先、离线复检 | PatchCore 或 DDAD | CFA | 在线 diffusion | [P9][P18][P10] |
| 完全没有异常样本且只要图像级 OK/NG | CutPaste / 统计纹理 | 模板差分 | 需缺陷像素标注的监督分割 | [P6][P1] |

## 5. 训练与阈值策略

1. **OK 集质量优先**：覆盖光照、批次、姿态、镜头污染初期、增益变化；混入隐性缺陷会把正常分布拉偏。
2. **SKU/相机/光源分筒**：每套成像条件单独建模与阈值；多 SKU 混线时不要强行共享阈值。
3. **阈值初值**：用 OK 验证集异常分的高分位数（如 99.9% 或最大值加裕量）设初值；再用少量真实异常校准漏检。
4. **指标**：图像级用 AUROC；像素定位用 AU-PRO / PRO 曲线；上线验收用真实产线漏检率（escapes）与误报率（false alarms）。MVTec AD 论文已指出高 AUROC 不等于高定位质量 [P1][P14]。
5. **漂移监控**：SPC 监控正常样本分数分布、光源老化、镜头污染；定期重校准阈值或重训。

## 6. 部署与推理加速

### 6.1 不损失召回的加速

| 措施 | 做法 | 风险 |
|---|---|---|
| ROI 先定位后推理 | 模板匹配/边缘定位后只推理有效区域 | ROI 不能过紧，需覆盖缺陷可能出现区 |
| 全卷积一次提特征 | 避免逐 patch 重复前向 | 需与训练特征层一致 |
| FP16 / TensorRT / OpenVINO | 边缘 GPU/VPU 常用 | 上线前用真实弱缺陷验证 |
| 异步流水线 | 采集、预处理、推理、后处理分级并行 | 增加内存与时延抖动 |
| batch=1 优化 | 低延迟场景优先 | 吞吐与延迟需权衡 |

### 6.2 会损失召回的加速（慎用）

| 措施 | 损失机制 |
|---|---|
| 降分辨率 | 直接丢失亚像素/细线划痕 |
| 大 stride / 无重叠滑窗 | patch 边界附近缺陷漏检；细划痕建议 stride ≤ patch/2 |
| 过度 PCA / coreset 压缩 | 正常模式覆盖不足，弱异常距离被压缩 |
| ANN 近似 kNN | 漏掉真正最近邻导致弱异常分数偏低 |
| 未校准 INT8 | 异常分差异被量化抹平，浅脏污/弱划痕漏检 |
| 过度 ROI 收缩 | ROI 外缺陷直接漏检 |

### 6.3 线扫特例

- 条带切分推理时保留 halo/overlap，保证 patch 感受野完整。
- 行频、曝光、运动速度必须匹配；运动模糊造成的划痕断裂不能靠后处理恢复。
- 连续幅面建议按“纵向位置 + 横向 lane”做分数聚合，避免把拼接边界误报为缺陷。

## 8. 对本项目（VisionSystem）的落地建议

1. **参数层**：形状匹配已有 `Symmetric` 开关；无监督检测可作为独立节点接入，参数至少包含 `ModelPath / Threshold / PatchSize / Stride / Device / MaxBatch / UseRoi`。
2. **结果层**：输出图像级 OK/NG + 像素热图；热图作为 `AuxShapes` 或独立图层，不进主结果明细，沿用项目“文案唯一出口”铁律。
3. **阈值层**：按流程/相机/SKU 存配置，不把阈值写死在模型里；提供“用当前 OK 批校准阈值”工具。
4. **部署层**：ONNX 作为中间格式；Release 用 OpenVINO/TensorRT 后端，Debug 先走 CPU；INT8 必须提供 A/B 漏检报告后才允许上线。
5. **优先级**：先实现 PaDiM/EfficientAD 两类代表模型 + 统计纹理基线，再考虑 DRAEM/CFA；不要先做 diffusion。
