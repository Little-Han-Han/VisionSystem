## 1. Shape Context —— Belongie, Malik, Puzicha（NIPS 2000）

**来源**
- *Shape Context: A New Descriptor for Shape Matching and Object Recognition*，S. Belongie, J. Malik, J. Puzicha，NIPS 2000, pp.831-837。
- 姊妹篇 *Matching with Shape Contexts*，S. Belongie, J. Malik，IEEE Workshop on Content-Based Access of Image and Video Libraries (CBAIVL) 2000。
- PDF：<https://vision.ucsd.edu/sites/default/files/publications/pdfs/Matching%20with%20Shape%20Contexts.pdf>
- 摘要页：<https://mlanthology.org/neurips/2000/belongie2000neurips-shape>

### 原理

核心思想：**「一个点的形状，就是其他点相对它排布的直方图」**。

设形状是一组采样轮廓点 `P = {p_1..p_N}`，对点 `p_i`，统计所有其他点相对它的偏移向量
`(x_j - x_i, y_j - y_i)`，并按**对数极坐标**分箱：

- 半径方向：`r_k = λ · (e^{k·b_r} - 1)`（λ 为标度参数，常取 0.1、`b_r`≈5 bins/decade）
- 角度方向：均分 `b_θ` 个扇区（常取 12）

得到直方图 `h_i(k)`，它既是局部描述子，又含蓄了整体形状。

不变性做法：
- **平移**：只统计相对坐标，天然不变；
- **缩放**：所有距离先除以标度 `λ`（论文用**中位距离**，抗离群比均值更稳）；
- **旋转**：角度一律相对**该点切向角**来量，于是完全旋转无关；
- **遮挡**：用 `log(距离)` 分箱（远处点权重小），被遮住一段时，远处的点仍能找到对应，鲁棒性强于欧氏分箱。

### 如何实现（落地管线）

```
1. Canny/轮廓提取 → 得到密集边缘像素
2. 从边缘像素里均匀采样 N 个点（N≈200~800），不需要角点、曲率极值等关键点
3. for each 采样点 pi:
     对所有其他点 pj 求相对偏移 → log-polar 分箱 → 归一化直方图 h_i(bins)
4. 对应（correspondence）求解：把 h_i 当作点点的属性向量
     代价 C = Σ_i [ C_S(p_i, q_β(i)) + β · C_A(p_i, q_β(i)) ]
     C_S = 两个直方图的 χ² 距离  = ½ Σ (h_i(k) − ĥ_j(k))² / (h_i(k) + ĥ_j(k))
     C_A = 切向角度之差（局部外观项）
5. 求使 C 最小的 β(·) → 二分图最小权匹配
   精确解用 Hungarian（O(N³)），实时场景直接退化为「按 h_i 最近邻取对应」的贪心（O(N²)）
6. 由对应点对拟合变换 → 得到相似度分数与位姿
```

数据结构：直方图 `vector<float>[N][b_r*b_θ]`（≈800×60 维浮点），对应矩阵 `N×N` 代价表。

### 与本项目 `algo_shape.cpp` 的关系

- **相同骨架**：都是「采样轮廓点 + 每个点带一个**局部方向属性**」，再用对应/一致性求相似度。
- **不同点（关键取舍）**：Shape Context 走**直方图 + 全局对应搜索**（O(N³) 匈牙利），为了识别（retrieval）场景牺牲速度；
  本项目走**固定模板 + 位姿网格扫描 + 平均余弦相似度**，因为工业定位要的是**精确位姿（x,y,θ,s）而不是「像不像」**。
- **可借鉴的点**：
  1. 论文用「中位距离」定标度 → 本项目缩放搜索靠显式 scale 网格，可以改成「模板特征点相对中心的径向分布」辅助定标，减少无效 scale。
  2. 分箱直方图是整数统计 → 可以直接用 SSE 的 `_mm_add_epi` 累加，比浮点点积更省；代价是精度损失。
  3. 遮挡下「远点仍可对应」的思路，可以转成本项目里**按点分「可靠/可疑」两档**的可选机制（见 §7）。

## 2. HALCON shape-based matching（MVTec）—— 工业基准

**来源**
- MVTec HALCON 参考手册：`create_shape_model` / `find_shape_model` / `determine_shape_model_params`（商用，文档公开）。
- 该算法本身申请了欧洲专利；公开的技术描述可参见 ESA 技术报告 *High Accuracy Matching of Planetary Images* 第 2.1 节（明确引用 HALCON 形状匹配与对应专利）：<https://sci.esa.int/c/portal/doc.cfm?fobjectid=40238>
- 中文原理综述（可读性最好的二手资料）：HALCON 算子手册解析 <https://devpress.csdn.net/v1/article/detail/151802492>

### 原理

一句话：**用「边缘点的梯度方向」而不是灰度值做匹配**，因此光照整体明暗、对比度变化对结果几乎无影响（灰度变、梯度方向不变）。

设模板边缘点集 `E_T = {(x_i, y_i, θ_i, w_i)}`（θ 为梯度法线方向，w 为边缘强度权重），
搜索图边缘点集 `E_S`，寻找位姿 `(Δx, Δy, φ, s)` 使方向一致性最大：

```
score(Δx, Δy, φ, s) = Σ_i w_i · cos( θ_image( x_i, y_i ) − ( θ_template_i + φ ) − φ_scale(s) )
                       ───────────────────────────────────────────────────────────────────
                                        归一化（除以参与点的权重和）
```

在 HALCON 的官方表述里，score 是「**归一化后的交叉积之和**」：
- 两图案完全一样 → score = 1；
- 匹配过程中允许**丢弃最多 x% 的模板点**（`MinScore` / occlusion 容忍）→ score 相应下降；
- 算法在用户给定的姿态范围内**总是选 score 最高的匹配**。

### 如何实现（落地管线）

**训练阶段（`create_shape_model`）**

```
1. 手工/先验指定 ROI（必须两图都完整包含）
2. ROI 内跑 Canny/Sobel → 抽取边缘像素
3. 每个边缘点记三元组：(位置相对 ROI 中心, 单位梯度方向, 强度权重)
4. 生成多分辨率金字塔模型（对应 NumPyramidsLevels 参数），每层按 ReduceMode 抽稀（点抽稀 + 图像降采样）
```

**搜索阶段（`find_shape_model`）**

```
1. 对整张搜索图（受限 ROI）算一次梯度场 gx/gy（8bit/CV_32F），各金字塔层用下采样复用
2. 姿态枚举：for φ in [angle_start, angle_end) step angle_step:
             for s in [scale_min, scale_max) step scale_step:
                 计算当前位姿下每个模板点的绝对采样位置（一次算好，所有位置复用 ← 关键）
3. 最粗层（level = max）：全图跳步扫，每个位置取局部最优，保留 Top-K 候选
4. 逐层向下：只在上一层结果的邻域（位置 ±n，角度/缩放 ±1 步）精化
5. 最细层：亚像素 + 亚角度/亚缩放精化（双线性插值梯度场）
6. 非极大抑制 → 输出 (row, col, angle, score)，并可选输出匹配轮廓
```

**三条决定性能的实现技巧**（也是本项目的做法）：

| 技巧 | 做法 | 收益 |
|------|------|------|
| 位姿预计算 | 对每个 (φ,s) 只算一次「旋转缩放后的采样偏移 + 旋转后的方向单位向量」，所有候选位置复用 | 把三重循环里的大量 sin/cos 提到外层 |
| 金字塔 | 粗层定位、细层精化 | 搜索代价 O(1/f²)，层数越深越快 |
| 提前终止 | ① 理论上界：剩余点即使全满分也达不到阈值就放弃；② 贪婪启发（greediness）：已评估点平均分 < 阈值×greediness 就放弃 | 大模板/大搜索图提速数倍 |

### 与本项目 `algo_shape.cpp` 的关系（几乎同构）

本项目实现的就是 HALCON 这套 edge-based matching 的精简版，逐条对应：

| HALCON | 本项目 `algo_shape.cpp` | 对应位置 |
|--------|------------------------|---------|
| Canny/Sobel 抽边缘点 | `Canny(patch, edges, contrast, 2.5·contrast, 3, true)` + `Sobel` CV_32F | `TrainCore` |
| 每点 (位置, 方向, 权重) | `shape.pts[]` + `shape.dir[]`（单位向量） | `ShapeModel` |
| 点重要性排序 | 按梯度幅值 `mag` 降序 `std::sort` | `TrainCore` |
| ReduceMode 抽稀 | **网格去重（同格只留最强点）** `cell = ceil(min_feature_dist)` | `TrainCore` |
| 金字塔模型 | `pyrDown` 层级，层数由「最粗层模板 ≥8px 且图像 ≥32px」约束 | `FindShapeModel` |
| 姿态枚举 + 预计算 | `BuildPose(角度, 缩放)` 产出 `{ox, oy, rx, ry}`，循环顺序改为**姿态在外、位置在内** | `FindShapeModel` 粗扫 |
| Top-K 候选逐层精化 | 最粗层全扫取 `bestScore[]`，逐层 ±1/±2 步邻域精化 | 精化循环 |
| 亚像素 | 最细层双线性采样 + **角度/缩放联合精化各 ±1 搜索步长分 8 档** | `refine` 段 |
| greediness | `param.greediness`（默认 0.9）+ 理论上界双重提前终止 | `ScorePose` |
| MinScore 遮挡容忍 | 当前是**所有点等权求平均余弦**，没有 per-point 丢弃 | ⚠ 见 §7 |
| OpenMP / SIMD | `omp parallel for schedule(dynamic,512)` + SSE2 四路向量化 | `ScorePose` |

**可借鉴的三点**
1. `determine_shape_model_params` 的「自动估计对比度/层数」——本项目 `numContrast` 是手工值，可以补一个自动档（用 Canny 默认高低的 Otsu 式估计）。
2. 允许**丢弃低分点**后再归一化（HALCON 的 occlusion 模型）——比现在「全部点进分母」更抗遮挡。
3. 输出模板轮廓本身（HALCON 常配合 `get_shape_model_contour`）——本项目已导出 `va_get_shape_model_points`（位置+方向），可直接拿去画轮廓。

## 3. OpenCV `cv::matchShapes` / `cv::HuMoments` —— 全局不变矩

**来源**
- OpenCV 文档：`group__imgproc__shape`（`HuMoments` / `matchShapes`）—— <https://docs.opencv.org/4.x/d3/dc0/group__imgproc__shape.html>
- 源码：`modules/imgproc/src/matchcontours.cpp`

### 原理

用**图像的归一化中心矩**构造 7 个对平移/旋转/缩放（及镜像）不变的标量：

```
ν_ji = m_ji / m_00^{ (j+i)/2 + 1 }     （归一化中心矩）
hu[0] = ν20 + ν02
hu[1] = (ν20 − ν02)² + 4ν11²
hu[2] = (ν30 − 3ν12)² + (3ν21 − ν03)²
hu[3] = (ν30 + ν12)² + (ν21 + ν03)²
hu[4..6] = （三次混合项，见文档）
```

注意文档原话：这些不变性**建立在「无限分辨率」假设上**，对栅格化图像只是近似成立。

### 如何实现

```
1. findContours → 取轮廓（或直接吃灰度图）
2. moments(contour) → HuMoments() → 7 个 double
3. 为了让「小的但形状相似」不被数值压倒，先取 mi = sign(hi) · log10|hi|
4. 距离：
      I1 = Σ|1/mA_i − 1/mB_i|
      I2 = Σ|mA_i − mB_i|
      I3 = Σ|mA_i − mB_i| / |mA_i|
   三种 mode 本质都是 Hu 矩空间里的 L1 距离，区别只在是否取倒数/做归一化
5. 返回 0~∞ 的 dissimilarity（越小越像）
```

### 与本项目关系

- **优点**：O(N) 一次算完，速度极快，**天然支持任意角度/缩放/平移**。
- **致命缺点**：只给一个「像不像」的标量，**给不出位姿**（要位姿就得全图代价图搜索），而且对**局部遮挡/部分缺陷**极敏感（一个角缺了，高阶矩全变）。
- 本项目定位：可作为**「有没有这个形状」的快速预筛**（在金字塔粗层之前先过一遍 Hu 矩），或用于「缺陷检测：形状整体是否还正常」。不适合做定位主算法。

## 4. OpenCV contrib `modules/shape` —— 开源版 Shape Context / Hausdorff

**来源**
- OpenCV 文档 `modules/shape` "Shape Distance and Matching"—— <https://docs.opencv.org/3.0-beta/modules/shape/doc/shape.html>
- 示例：`modules/shape/samples/shape_example.cpp`（读 `../data/shape_sample` 里的一对图，输出最近邻排序）
- Rust 绑定索引可查：`opencv::shape`（`ShapeContextDistanceExtractor` / `HausdorffDistanceExtractor` / `ThinPlateSplineShapeTransformer` 等）

### 原理与实现

这一模块把 §1 的 Shape Context **工程化**，接口是统一的 `ShapeDistanceExtractor::computeDistance(contour1, contour2) -> float`：

| 类 | 原理 | 实现要点 |
|----|------|---------|
| `ShapeContextDistanceExtractor` | §1 的 log-polar 直方图 + χ²/EMD 代价；支持切向角、形变弯曲能 | 参数：`setAngularBins` / `setRadialBins` / `setInnerRadius` / `setOuterRadius` / `setShapeContextWeight` / `setImageAppearanceWeight` / `setBendingEnergyWeight` / `setTransformAlgorithm` |
| `HausdorffDistanceExtractor` | 点集 Hausdorff 距离（对称版 + rank proportion 抗噪） | 两套代价矩阵，KDTree 加速近邻查询 |
| `ThinPlateSplineShapeTransformer` | TPS 薄板样条形变 | `setRegularizationParameter`；用于**可形变匹配**（柔性件） |
| `AffineTransformer` / `ShapeTransformer::estimateTransformation` | 位姿估计 | 由对应点对拟合仿射（§1 的第 5 步） |
| `HistogramCostExtractor` 系列 | 直方图代价：Norm / EMD / Chi / EMDL1 | 影响 C_S 项的计算方式 |

### 与本项目关系

- 这是**最接近本项目思路的开源实现**（同样是「轮廓点 + 局部方向/直方图属性 + 距离」），可以直接当参考实现翻源码对照。
- **但它做的是「形状相似度/检索」**：`computeDistance` 只吐一个距离，位姿要靠 `estimateTransformation` 反解。
  本项目要的是「**给定姿态范围，求最优位姿**」，这是**搜索问题**不是**比较问题**——这也是二者的分水岭。
- **可借鉴**：`Hausdorff` 的 rank-proportion 抗噪（用「前 k% 近邻的平均距离」代替最坏值），可以升级本项目的 `ScorePose`：
  现在用「所有模板点的平均余弦」，改成「取最差的 q% 点做截断平均（trimmed mean）」，遮挡鲁棒性会明显变好。

## 5. OpenCV `cv::matchTemplate`（TM_CCOEFF_NORMED）—— 灰度 NCC

**来源**
- OpenCV 教程 Template Matching—— <https://docs.opencv.org/3.0.0/de/da9/tutorial_template_matching.html>
- 源码：`modules/imgproc/src/templmatch.cpp`；OpenCL kernel：`modules/imgproc/src/opencl/match_template.cl`

### 原理

滑动窗口求相似度，6 种方法中最常用的是归一化互相关：

```
R(x,y) = Σ_{x',y'} ( T'(x',y') · I'(x+x', y+y') )  /  sqrt( Σ T'² · Σ I'² )

其中  T'(x',y') = T(x',y') − mean(T)
      I'(x+x',y+y') = I(x+x',y+y') − mean(I(x+x',y+y'))
```

### 如何实现（速度是它真正的价值）

```
1. matchTemplate 统一先把「模板卷积图」算好，几种 method 共享这部分
2. TM_CCOEFF_NORMED 需要 ΣI 与 ΣI² → 用积分图（integral）一次扫出，避免每位置重算
3. 大模板（>某阈值）走 crossCorr / DFT（mulSpectrums 取共轭即互相关）
4. 小模板走 hal:: 通用 SIMD 后端（SSE/AVX/NEON，见 modules/core/include/opencv2/core/hal/intrin.hpp）
5. UMat + OpenCL 走 match_template.cl（CCORR / SQDIFF / CCOEFF 宏开关）
6. minMaxLoc 取全局极值 → 最多只有一个平移位姿
```

### 与本项目关系

- **本项目现有的 `va_match`（`va_match_template`）就是它**：8bit 灰度 + `TM_CCOEFF_NORMED`，**只支持平移**。
- 为什么还另做形状匹配：`matchTemplate` 在旋转/缩放时**结果会崩**（模板和窗口错位，归一化后分数反而可能接近 1，产生假阳性）。
- **可借鉴**：积分图这一招对本项目也适用——评分时需要「该位置邻域内梯度场的统计」，若改成**用积分图预计算局部 Σg、Σg²、Σ|g|**，就能省掉双线性采样里的部分加法，且对非边缘区域（平滑区）更稳。

## 6. ORB（Rublee, Rabaud, Konolige, Bradski，ICCV 2011）—— 对照组

**来源**
- *ORB: an efficient alternative to SIFT or SURF*，ICCV 2011。PDF：<https://sites.cc.gatech.edu/classes/AY2024/cs4475_summer/images/ORB_an_efficient_alternative_to_SIFT_or_SURF.pdf>
- OpenCV 官方文档 `features2d`：<https://docs.opencv.org/>

### 原理

FAST 角点 + 旋转 BRIEF 二进制描述子：

```
1. oFAST：金字塔各层跑 FAST 角点 → Harris 响应排序取前 N → 强度质心定方向
         θ = atan2( m01, m10 ),  m_pq = Σ x^p y^q I(x,y)（patch 内）
2. rBRIEF：对 n 个测试点对 (a_i, b_i) 做二值比较 I(a)<I(b) → 256 bit 串（32 字节）
         - 旋转：所有点对先绕质心转 θ（量化成 30 个角度档，预制 LUT）
         - 去相关：离线贪心搜索一批「方差大（均值≈0.5）且互不相关」的测试对
3. 匹配：汉明距离 = popcount(x ⊕ y)（几条机器指令）；配 ratio test（0.7~0.8）+ RANSAC
```

### 为什么它「不适合」本项目场景（重要结论）

| 维度 | ORB / 点特征法 | 边缘轮廓形状匹配（本项目） |
|------|---------------|--------------------------|
| 前提 | 目标要有**丰富纹理**（角点足够） | 只要**轮廓清晰**即可 |
| 工业零件（无纹理/金属面） | ❌ 常常凑不出 8~10 个可靠角点 | ✅ 边缘天然存在 |
| 亚像素精度 | 靠角点定位，受纹理质量制约 | 靠梯度场插值，可达 0.1 px 级 |
| 输出 | 一堆 2D 点对应 → 需拟合 | 直接输出 (x, y, θ, s) |
| 视角变化 | ✅ 天然支持（单应/平面） | ❌ 只支持平面内旋转缩放 |

**结论**：本项目（工业零件平面定位）走边缘轮廓路线是正确选择；ORB 只在「目标有明显纹理且视角会变」时才值得考虑。

## 7. 选型对照与本项目落地清单

### 7.1 四类方法对照

| 方法 | 平移 | 旋转 | 缩放 | 局部遮挡 | 光照变化 | 速度 | 工程复杂度 |
|------|------|------|------|---------|---------|------|-----------|
| 灰度 NCC（§5） | ✅ | ❌ | ❌ | ⚠ | ❌ | 快 | 低 |
| Hu 矩（§3） | ✅ | ✅ | ✅ | ❌ | ⚠ | 极快 | 低（仅分数） |
| Shape Context（§1/§4） | ✅ | ✅ | ✅ | ✅ | ✅ | 慢（O(N³) 匈牙利） | 高 |
| **边缘梯度+位姿扫（§2 ← 本项目）** | ✅ | ✅ | ✅ | ✅ | ✅ | 中~快 | 中 |

### 7.2 本项目 `algo_shape.cpp` 数据流

```
训练   Bitmap(任意格式) → GrayInput(8bpp 灰度, pinned)
       → Canny(contrast, 2.5×, L2) 抽边缘 → Sobel 求 gx/gy 降序
       → 网格去重（cell=ceil(min_feature_dist)）→ ShapeModel{pts, dir, w, h}
       → va_create_shape_model_ex / va_get_shape_model_points（可导出画特征图层）

搜索   Bitmap → GrayInput → pyrDown 建 L0..Lk 层梯度场
       → 最粗层：姿态(φ,s) 在外、位置在内；BuildPose 预计算 {ox,oy,rx,ry}
       → ScorePose：平均余弦相似度 + 理论上界/贪婪双重提前终止（SSE2 四路）
       → bestScore[] 取 Top-K → 逐层邻域精化 → 最细层亚像素（角度+缩放 8 档）
       → NMS 去重 → VA_ShapeMatch{cx, cy, angle, scale, score, w, h}
```

### 7.3 后续最值得借鉴的三件事（优先级从高到低）

1. **遮挡容差（对应 HALCON 的 MinScore）** —— 现在是「所有模板点等权进分母」，被遮挡一半就掉分。
   建议：评分时对「余弦 < 某局部阈值」的点计为 out-of-figure，只参与分子不参与分母，并输出 `score` 与 `used_ratio` 两个量。
2. **截尾平均（对应 modules/shape 的 rank/ Hausdorff）** —— 用「最差 q% 点截断」替代纯平均，抗噪更稳（§4）。
3. **自动训练参数** —— 模仿 `determine_shape_model_params`：用 Otsu/梯度直方图的自动阈值估计 Canny 的对比度，并把特征点数自动设在 100~600。

## 8. 一句话小结

- **要「有没有这个形状」（形状分类/缺陷判定）** → Hu 矩（§3）。
- **要「形状像不像，给个相似度」（检索/聚类）** → Shape Context（§1 / §4）。
- **要「刚体零件在哪、转了多少度、放大了多少倍」（工业定位）** → **边缘梯度 + 金字塔 + 位姿扫描**（§2）—— 也是 `VisionAlgo.Native` 现在的实现。
- **目标有纹理、视角还会变** → ORB / SIFT（§6）。
