# 通讯架构重构方案：从「端点配置」到「点位 + 消息 + 任务」

> 目标：让通讯从"每条流程里手写发送/接收节点"升级为**可配置的交互层**，
> 原生支持心跳、Ready/Busy、触发、结果推送、跨流程汇总，并且新增协议（OPC UA 等）
> 不需要改核心代码。
>
> **实现状态（2026-11-08）**：Phase 0-3 已落地（OPC UA 驱动因缺少外部 SDK 暂未实现，
> 插件加载与点位/任务框架已就绪）。旧 `CommRegistry` API 与 SendData/ReceiveData 节点保持兼容。
>
> 已实现：点位表 / 消息模板 / 任务引擎 / 每端点发送队列 / 心跳 / Ready-Busy-Fault 流程绑定 /
> 跨流程 AllFresh 汇总 / 协议插件加载 / `CommAutomationForm` 配置界面。
>
> 关联代码：`Communication/CommHub.cs`、`CommPointMapper.cs`、`CommSendQueue.cs`、
> `CommTemplate.cs`、`CommJobEngine.cs`、`CommProtocolRegistry.cs`、`CommAutomationForm.cs`、
> `Core/AppSettings.cs`（CommSettings v2）、`Framework/Communication/CommContracts.cs`。

---

## 1. 结论（推荐方案）

采用 **B 方案：点位（Point）+ 消息模板（Message）+ 任务（Job）** 三层模型：

```text
流程 / 脚本 / 主界面
        │  只认"点位名 / 消息名 / 任务名"
        ▼
CommHub（统一门面：读写点位、发消息、等待信号）
        │
        ├── PointTable（点位表：名称 → 协议地址 / 类型 / 方向 / 缩放）
        ├── MessageTemplate（文本 / JSON / 二进制帧 + 占位符）
        └── JobEngine（心跳、Ready/Busy、触发、结果推送、跨流程汇总）
        │
        ▼
ICommChannel（统一读写 / 订阅 / 状态）
        │
        ├── TcpClientDriver / TcpServerDriver
        ├── ModbusTcpDriver
        └── OpcUaDriver / 其它（协议插件 DLL，运行时加载）
```

**核心变化**：

1. 流程不再关心"TCP 还是 Modbus、地址是 40001 还是 ns=2;s=..."，只写 `Comm.Set("Line1.Busy", true)`；
2. 心跳 / Ready / Busy / 结果推送由 **Job** 常驻执行，不再占用流程节点；
3. 跨流程汇总由 `FlowResultHub` 统一收口，按"产线/工位"分组生成一条组合消息；
4. 新协议 = 实现 `ICommProtocolFactory` 的 DLL，放进 `Protocols\`，核心零改动。

## 2. 现状与痛点（代码事实）

| # | 现状 | 位置 | 造成的限制 |
|---|---|---|---|
| 1 | 协议是枚举 + `switch` | `CommRegistry.Channel` / `SendText` / `ModbusRead` | 加 OPC UA 要改枚举、注册表、界面、配置四处 |
| 2 | 只有"端点"概念，没有点位 | `CommEndpointConfig` | 每条流程节点重复填地址；PLC 改地址要逐节点改 |
| 3 | 发送只支持整段文本或单寄存器 | `RunSendData` | 组合信息（流程1+流程2）只能靠脚本拼字符串 |
| 4 | 接收是**流程线程轮询 Sleep** | `RunReceiveData` 的 `while + Thread.Sleep(20)` | 等待 ack 时整条流程被阻塞，最多 2s；并发流程白占线程 |
| 5 | 没有心跳 / 定时任务 | 无 | 只能靠流程循环顺带发，流程停了心跳就停 |
| 6 | 没有 Ready/Busy 状态机 | 无 | 上位机不知道设备是否可接料，容易重复触发 |
| 7 | 多流程共用一个连接时无发送队列 | `TcpClientSession.Send` 直接写 | 高频并发下消息可能交错（尤其二进制/多帧协议） |
| 8 | 跨流程汇总无统一入口 | `FlowOutputChannel` 只广播单流程结果 | 组合信息需再建一条"汇总流程"，绕 |
| 9 | 协议插件不是真插件 | `CommKind` 静态枚举 | 无法按客户现场裁剪/扩展协议 |

## 3. 目标分层与职责

| 层 | 类型 | 职责 | 不该做什么 |
|---|---|---|---|
| 交互层 | `CommHub` | 点位读写、消息发送、等待信号、任务生命周期 | 不解析协议字节 |
| 编排层 | `JobEngine` + `FlowResultHub` | 心跳、Ready/Busy、触发、结果汇总、重试 | 不直接碰 Socket |
| 映射层 | `PointTable` + `MessageTemplate` | 名称→地址、类型转换、模板渲染 | 不管理连接 |
| 通道层 | `ICommChannel` | 连接、发送、读取、订阅、状态事件 | 不认识流程/业务 |
| 协议层 | `ICommProtocolFactory` | 创建具体协议驱动（TCP/Modbus/OPC UA） | 不依赖 WinForms |
| 传输层 | Socket / SDK | 字节收发 | — |

依赖方向：**上层 → 下层**；协议插件只依赖契约，不依赖宿主。

## 4. 核心模型

### 4.1 端点（Endpoint）

沿用现有 `CommEndpointConfig`，补三个字段：

```csharp
public sealed class CommEndpointConfig
{
    // 既有：Name / Kind / Host / Port / SlaveId / Enabled / AutoConnect

    public string Framing { get; set; }      // None / Newline / LengthPrefix / StxEtx
    public int    ReconnectMs { get; set; }  // 断线重连间隔，0=不自动重连
    public int    TimeoutMs { get; set; }    // 单次读写超时
}
```

### 4.2 点位（Point）——协议的"统一语言"

```csharp
public enum CommPointDirection { Read, Write, ReadWrite }
public enum CommPointType { Bool, Int16, Int32, Float, String, Json }

public sealed class CommPoint
{
    public string Name { get; set; }          // 全局唯一：Line1.Ready / Line1.Busy / Line1.Trigger
    public string Endpoint { get; set; }      // 端点名
    public string Address { get; set; }       // 协议地址：40001 / HR:0 / ns=2;s=Line1.Ready
    public CommPointDirection Direction { get; set; }
    public CommPointType Type { get; set; }
    public double Scale { get; set; } = 1;    // 工程值 = 原始值 * Scale + Offset
    public double Offset { get; set; }
    public string Default { get; set; }       // 初始值 / 断线回落值
    public string Description { get; set; }
}
```

同一点位在不同协议下的地址示例：

| 点位 | TCP 文本 | Modbus TCP | OPC UA |
|---|---|---|---|
| `Line1.Trigger` | `TRIG`（收到即触发） | `HR:100`（bit0） | `ns=2;s=Line1.Trigger` |
| `Line1.Ready` | `READY 1` | `CO:0` | `ns=2;s=Line1.Ready` |
| `Line1.Result` | `RESULT,OK,12.3` | `HR:200..203`（4 寄存器） | `ns=2;s=Line1.Result` |

### 4.3 消息模板（MessageTemplate）

```csharp
public sealed class CommMessageTemplate
{
    public string Name { get; set; }          // ResultLine1 / Heartbeat / TriggerAck
    public string Endpoint { get; set; }
    public string Format { get; set; }        // 见下
    public string Mode { get; set; }          // Text / Json / Binary / Points
    public string Terminator { get; set; }    // "\r\n" / "" / 长度前缀
    public List<CommMessageField> Fields { get; set; }
}
```

- `Text`：`"RESULT,{Line1.Passed},{Line1.ElapsedMs},{Line1.Yield:F2}\r\n"`
- `Json`：`{"line":"L1","f1":"{Flow1.Passed}","f2":"{Flow2.Passed}","yield":{Line1.Yield}}`
- `Binary`：字段级 `Offset/Type/Endian`，用于 PLC 固定帧
- `Points`：不拼报文，直接把字段写到多个点位（Modbus/OPC UA 常用）

占位符统一由 `CommValueBag` 提供：`{Flow1.Passed}` / `{Flow1.ElapsedMs}` / `{Line1.Yield}` /
`{Count.Ok}` / `{Count.Ng}` / `{Time}` / `{CycleId}`。

### 4.4 任务（Job）——把"频繁交互"从流程里拿出来

```csharp
public sealed class CommJob
{
    public string Name { get; set; }
    public bool Enabled { get; set; }
    public string Trigger { get; set; }        // Timer / ResultGroup / PointEdge / Startup
    public int IntervalMs { get; set; }        // Timer / 超时
    public List<string> Flows { get; set; }    // ResultGroup 的成员流程
    public List<CommAction> Actions { get; set; }
}

public sealed class CommAction
{
    public string Kind { get; set; }   // SetPoint / SendMessage / WaitPoint / Sleep / StartFlow / Log
    public string Target { get; set; } // 点位名 / 消息名 / 流程 Id
    public string Value { get; set; }  // 常量或占位符
    public int TimeoutMs { get; set; }
    public bool ContinueOnError { get; set; }
}
```

四类常用 Job：

| Job | 触发 | 动作（示例） |
|---|---|---|
| **心跳** | `Timer` 1000ms | `SetPoint Heartbeat = toggle` 或 `SendMessage PING` |
| **结果推送** | `ResultGroup`（流程1+流程2） | `SetPoint Busy=true` → `SendMessage ResultLine1` → `WaitPoint Ack` → `SetPoint Busy=false` → `SetPoint Ready=true` |
| **触发启动** | `PointEdge`（Trigger 上升沿） | 去抖 → `StartFlow F1,F2` → `SetPoint Busy=true` |
| **状态镜像** | `ResultGroup` / `Timer` | `SetPoint Line1.OkCount / NgCount / Yield` |

> 这些任务由 `JobEngine` 的后台调度器执行，**流程线程只负责出结果**，不再 Sleep 等 ack。

## 5. 关键机制

### 5.1 每端点一个发送队列（必须）

多个流程/任务同时写同一个连接时，必须保证**一条消息的字节连续**，否则二进制协议会错帧。

```text
CommHub.SendAsync(endpoint, message)
   → 按 Endpoint 分组的 Channel<OutboundFrame>（优先级：Alarm > Result > Heartbeat）
   → 单写线程按序写 Socket → 完成后 TaskCompletionSource 返回
```

- 流程节点调用 `SendAsync` 只入队，不阻塞；需要 ack 时再 `WaitPoint`。
- 队列满时丢弃低优先级（心跳），保留结果/报警，并计数告警。

### 5.2 心跳与重连

- `HeartbeatJob` 固定周期执行，带**漂移补偿**（按上一次实际时间排下一次）；
- 连续 N 次失败 → 端点状态 `Faulted`，触发 `ReconnectMs` 退避重连；
- 心跳内容支持：写 bool 翻转、写递增计数、发文本 `PING`、写多个点位；
- 断线期间结果消息进入队列（有上限），恢复后按策略补发或丢弃并标记 `Stale`。

### 5.3 Ready / Busy 状态机

```text
Idle --触发--> Busy --结果已发+Ack--> Ready --下一触发--> Busy
                  └─ 超时/失败 → Faulted（保持 Busy，等人工/自动复位）
```

- `Ready`/`Busy` 互斥，由 `PointTable` 保证；
- 任务开始先 `Busy=true, Ready=false`，结束（含失败）必须回到确定状态；
- 提供 `ForceReset` 点位/按钮，避免异常后卡死。

### 5.4 触发（输入）

| 协议 | 实现 |
|---|---|
| TCP 文本 | 收到匹配 `Trigger` 模板的帧 → 事件 |
| Modbus | 按 `PollMs` 批量读触发区（一次 FC03 读多个点），检测上升沿 |
| OPC UA | `MonitoredItem` 订阅，服务端推送，无轮询 |

触发去抖：同一 `CycleId` 内只启动一次；`Busy` 期间新触发可选择忽略/排队。

### 5.5 跨流程结果汇总

`FlowResultHub` 订阅 `FlowOutputChannel`，维护：

```csharp
sealed class FlowResultSnapshot
{
    public string FlowId, FlowName, Product;
    public bool Passed;
    public int ElapsedMs;
    public long CycleId;        // 新增：同一帧的关联号
    public DateTime Time;
}
```

两种汇总模式：

| 模式 | 规则 | 适用 |
|---|---|---|
| `Latest` | 任一流程出结果就发，未更新的流程用上次值（标记 stale） | PLC 只要最新状态 |
| `AllFresh`（推荐） | 组内所有流程的 `CycleId` 相同且在 `WindowMs` 内到齐才发 | 组合判定必须同帧 |

> 需要在 `FlowOutputEventArgs` 追加 `CycleId`（long，向后兼容）。由 `FlowRunSlot` 在每帧开始时
> `Interlocked.Increment` 生成，`FlowRunManager` 可让同组流程共享一个 CycleId（按触发批次）。

### 5.6 接收不再阻塞流程线程

`RunReceiveData` 的 `while + Thread.Sleep(20)` 改为：

```csharp
// 等待"某个点位变化"或"收到匹配帧"
OpResult<CommValue> r = await CommHub.WaitPointAsync("Line1.Ack", timeoutMs, token);
```

底层用 `TaskCompletionSource` + 事件/订阅唤醒；流程节点等待时释放线程（或统一改为异步节点执行）。
短期若不想改 FlowRunner 为 async，可先提供**同步等待但由事件唤醒**的 `WaitPoint(name, timeout)`，
内部 `ManualResetEventSlim`，不再 20ms 轮询。

## 6. 协议适配与插件

### 6.1 契约

```csharp
public interface ICommProtocolFactory
{
    string Kind { get; }                       // "TcpClient" / "ModbusTcp" / "OpcUa"
    ICommChannel Create(CommEndpointConfig cfg, CommPointTable points);
}

public interface ICommChannel : IDisposable
{
    string Kind { get; }
    bool IsConnected { get; }
    string StatusText { get; }

    event EventHandler<CommStateEventArgs> StateChanged;
    event EventHandler<CommFrameEventArgs> FrameReceived;   // 原始帧/文本
    event EventHandler<CommPointEventArgs> PointChanged;    // 订阅点位（可选）

    Task<OpResult> ConnectAsync(CancellationToken token);
    Task DisconnectAsync();

    Task<OpResult> SendAsync(CommFrame frame, CancellationToken token);
    Task<OpResult<CommValue>> ReadAsync(CommPoint point, CancellationToken token);
    Task<OpResult> WriteAsync(CommPoint point, CommValue value, CancellationToken token);
    Task<OpResult> SubscribeAsync(IEnumerable<CommPoint> points, CancellationToken token);
}
```

### 6.2 加载方式（沿用模块包的做法）

```text
bin\x64\<cfg>\
├── VisionPlatform.exe
├── Communication\                 ← 可选：第三方协议驱动
│   ├── VisionPlatform.Comm.OpcUa.dll
│   └── Vendor.Xxx.dll
└── Modules\...
```

- `ProtocolRegistry` 扫描 `Communication\*.dll`，反射找 `ICommProtocolFactory`；
- 单个 DLL 加载失败只记日志，不影响内置 TCP/Modbus；
- 内置驱动编译进宿主，第三方驱动只引用 `VisionPlatform.Framework` 的通讯契约。

> **OPC UA 的现实约束**：本项目坚持"零 NuGet"。OPC UA 栈（Opc.Ua.Client / 第三方 SDK）
> 需要以**外部 DLL** 形式放 `ThirdParty/OPCUA`，再由 `VisionPlatform.Comm.OpcUa.dll` 引用；
> 不建议把 OPC UA 栈直接塞进宿主（体积、许可、升级都不好控）。

### 6.3 各协议实现要点

| 协议 | 通道实现 | 点位映射 | 备注 |
|---|---|---|---|
| TCP 客户端 | 现有 `TcpClientSession` 包一层 | 文本帧 / 模板匹配 | 补 Framing（换行/长度/STX-ETX） |
| TCP 服务端 | 现有 `TcpServerSession` | 同上，按客户端会话区分 | 多客户端时结果广播策略要可配 |
| Modbus TCP | 现有 `ModbusTcpClient` | `HR/IR/CO/DI:offset` + 类型/字序 | 批量读（一次 125 寄存器）、写多寄存器 FC16 |
| OPC UA | 新插件 | `ns=2;s=...` NodeId | 订阅优先；断线重连 + 会话重建 |
| 串口/其它 | 新插件 | 自定义 | 同一套 Job 不变 |

## 8. 界面调整（CommForm）

已实现为独立窗体 `CommAutomationForm`（从通讯界面「点位/任务…」进入），含以下页签；
原通讯窗体继续负责端点配置与手动收发：

| 页 | 内容 |
|---|---|
| **端点** | 名称、协议（下拉由 `ProtocolRegistry` 提供）、Host/Port、Framing、重连、超时、连接/断开、状态灯 |
| **点位** | 表格：名称 / 端点 / 地址 / 方向 / 类型 / 缩放 / 默认值 / 说明；支持 CSV 导入导出、批量改名 |
| **任务** | 表格：名称 / 触发 / 周期或流程组 / 动作列表；启用开关、试运行、最近执行结果 |
| **诊断** | 每端点：状态、收发字节/帧计数、最后错误、最后收发内容、心跳失败次数、队列积压；手动发送/读取 |

流程节点简化为两类（旧节点保留）：

- `通讯动作 CommAction`：下拉选 Job 或 Point/Message，不再填协议细节；
- `等待信号 CommWait`：等待点位/帧，超时可跳过。

## 10. 方案对比

| 方案 | 描述 | 优点 | 缺点 | 结论 |
|---|---|---|---|---|
| A. 端点 + 任务 | 保留现在的端点/文本模型，只加 Job | 改动最小 | 仍无点位抽象，协议细节泄漏到任务/节点 | 过渡可用 |
| **B. 点位 + 消息 + 任务** | 本文方案 | 协议无关、组合信息简单、可插件扩展 | 需要一次配置模型升级 | **推荐** |
| C. 完整信息模型 | 仿 OPC UA 地址空间/订阅 | 最灵活 | 过度设计，团队学习成本高 | 暂不 |

## 11. 验收指标（建议）

1. **协议扩展**：新增 OPC UA 只增加 DLL + 配置，宿主零代码改动；
2. **心跳**：1s 周期抖动 < 50ms，连续 3 次失败进入 Faulted 并自动重连；
3. **结果汇总**：流程1/2 同帧结果到齐 → 组合消息在 20ms 内发出（p99）；
4. **并发**：4 条流程同时写同一端点，抓包无交错帧、无丢失；
5. **不阻塞**：等待 Ack 时流程线程不 Sleep（CPU 占用与无等待时一致）；
6. **兼容**：旧 `appconfig.json` 直接加载，旧 SendData/ReceiveData 行为不变。

## 12. 风险与注意事项

| 风险 | 说明 | 对策 |
|---|---|---|
| TCP 粘包/拆包 | 文本无分隔符时无法界定帧 | 明确 Framing；默认换行；二进制用长度前缀 |
| 多流程共享连接 | 并发写导致交错 | 每端点单写队列（§5.1） |
| OPC UA 依赖 | 零 NuGet 约束 | 外部 DLL + 插件目录；许可单独确认 |
| 配置迁移 | 旧字段缺失/新增字段 | SchemaVersion 升级 + 归一化（沿用 FlowSettings 做法） |
| 线程模型 | Job 线程 / 流程线程 / UI 线程 | 所有跨线程事件走队列/Invoke；Hub 内部锁最小化 |
| 断线补发 | 结果消息积压 | 队列上限 + 旧消息标记 Stale，不无限堆积 |

### 13.2 使用方式

1. 打开「通讯」界面 → 左侧「点位/任务…」；端点/点位/消息/流程均为下拉，新增行自带默认值；
2. **点位**：`Line1.Ready` → 端点 `PLC`、地址 `HR:100`、类型 Bool；
3. **消息**：`ResultLine1`，模板 `{"line":"L1","f1":"{Flow1.Passed}","f2":"{Flow2.Passed}"}`；
4. **任务**：`ResultGroup` + 流程 `F1;F2`（双击「流程」列勾选，或点「选择流程…」）+ 动作
   （双击「动作」列打开动作编辑器：下拉选点位/消息/流程，支持增删与上下移动）
   `SetPoint:Line1.Busy=true;SendMessage:ResultLine1;WaitPoint:Line1.Ack=true@500;SetPoint:Line1.Busy=false;SetPoint:Line1.Ready=true`；
5. **流程信号**：为每条流程配 `Busy / Ready / Fault` 点位（多相机、多流程各一行）；
6. 保存后立即生效（`ConfigStore.Changed` → `CommHub.Reload` / `CommJobEngine.Reload`）；
7. 所有新增行都带默认值（方向 ReadWrite、类型 Bool、字序 ABCD、任务 Timer/1000ms/Latest/500ms），
   端点/点位/消息/流程/触发模式均为下拉；新增配置后点「刷新下拉」即可更新选项。

### 13.3 当前边界

- Modbus 驱动目前只支持 `HR / IR` 保持/输入寄存器（`CO / DI` 会明确报错）；需要线圈时可扩展 `ModbusTcpClient`；
- 内置 TCP 只支持文本帧；二进制协议请走插件；
- 插件端点目前通过 `appconfig.json` 的 `Comm.Endpoints` 手工添加（旧端点界面只编辑 TCP/Modbus）；
- OPC UA：把 SDK 与适配器 DLL 放 `ThirdParty/Communication`，构建自动复制到 `bin\x64\<cfg>\Communication`；
  未放 SDK 时端点显示「协议插件未安装（OpcUa）」，不影响其它协议；
- 任务动作暂不支持条件/循环（`If`/`While`），复杂逻辑可先用脚本节点或拆多个任务。
