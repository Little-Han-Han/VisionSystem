## 1. 本次增量目标

1. **把"做字符模板"从一个"必须先知道 exe 在哪、还要按规则改文件名"的隐性知识，变成界面上看得见、点得到、能当场验证的操作**——现状是目录为空、界面无入口、失败无提示，用户只会得到一个结论："这软件不认字"。
2. **让"结果"在工程师需要判断的那一秒就能被读懂**：右栏总高 637 px 里参数区只剩 185 px、结果表 7 列挤在 288 px 里必须横向拖、匹配分数和 Blob 面积这两个最关键的数在界面上根本显示不出来——这不是"不够好看"，是**关键判据不可读**。
3. **消除三处"静默"**：空模板库静默跑成 OK、坏模板图静默跳过、切换节点静默清空结果。三处都会让用户误判"功能坏了"或"检测通过了"。

## 2. 用户故事

**需求 1（字符模板）**

1. 作为产线工程师，我希望在 OCR 节点的参数面板上点一个明确可见的入口就打开"字符模板库"，以便不用去文件管理器里翻 exe 目录、不用猜文件夹该叫什么。
2. 作为产线工程师，我希望在图像上框住一个字符、输入它的正确值、点一下"加入模板库"，以便用"看图说话"的方式建立模板，而不是去改名一个图片文件。
3. 作为产线工程师，我希望模板库里能看到**已经有多少个字符、分别是什么、各有多少张样本**，以便确认"我到底配好了没有"，而不是跑一遍看结果猜。
4. 作为产线工程师，我希望模板库为空、目录不可写、某张模板图读不出来时，界面明确告诉我"是什么问题、该点哪里"，以便自己就能修，不用等人来现场。
5. 作为产线工程师，我希望软件升级或重装后我手工放好的模板还在、还能用，以便不用每个新版本都重建一次库。
6. 作为产线工程师，我希望识别错的那一块图能直接"加入模板库并改正标签"，以便在现场用几分钟把误识别调好，而不是回头重新做一遍库。

**需求 2（结果呈现）**

7. 作为产线工程师，我希望参数区不再被端子区和结果区挤成一条缝，以便调参时不用一直上下滚。
8. 作为产线工程师，我希望结果表在我这块屏上不用横向拖动就能看全每一条结果，以便"看一眼就知道过了没有"。
9. 作为产线工程师，我希望匹配分数、NCC 得分、Blob 面积/圆度、OCR 文本与字符数这些**判据数值**直接出现在画布上和我眼前，以便不用把鼠标移来移去或翻日志。
10. 作为产线工程师，我希望流程画布的节点卡片上就写着"3 个匹配 / 12 个 Blob / ABC-1234"，以便不点开节点也能看出这条流程跑出了什么。
11. 作为产线工程师，我希望点回上一个节点时还能看到它上次的结果（并标注是什么时候跑的），以便对比上下游节点，而不是每点一个节点都得重跑一次。

### 3.2 需求 2：结果呈现与布局（`UI-R`）

| 编号 | 需求 | 优先级 | 验收标准（可测） |

- 参数区内部改为**分组折叠 + 滚动**（模板 / ROI / 识别 / 显示 四组），保证 400 px 内不用长距离滚动。**分组折叠状态不持久化**：每次打开/切换节点一律**全部展开**（定案见 Q16，理由见 §6.1）。

- **结果区只显示「当前选中节点」一行（主行）+ 该节点的目标明细**（主理人已定案，见 Q14 附注）：**不做"所有节点常驻列表"**。理由：288 px 宽下把 5 个节点各占一行、每行还要塞状态 + 主判据 + 耗时，会重新变挤 —— 而这正是本次要解决的问题。同时它与 UI-R08 的"切回某节点立即回填"、C5-d 的"选中无结果节点"两条语义自洽（常驻列表下不存在"切回回填"这回事）。

**为什么全链概览放在画布上，而不是结果区（职责分工，Q14 附注的配套结论）**

| 谁 | 承担什么 | 理由 |
|---|---|---|
| **画布节点卡片**（UI-R06） | **全链概览**：每张卡片一行结果摘要；未运行显示"未运行"（不是 `0`）；**NG 时摘要行变色 + 红边** | 行数 = 执行节点数（通常 ≤ 10），**画布上 10 个节点是一屏看全的** |
| **结果区**（UI-R02） | **当前节点细节**：主行两行高 + 目标级明细 + 时间戳 | 180 px 只放得下 4 行、其余要滚动 |

> **结论：用滚动换概览不划算。** 因此"结果区只显示当前节点"并不是丢掉了全链状态 —— 它被移到了画布卡片上，并且**那里必须有视觉编码（NG 红边 + 摘要行变色，且与 OK / 未运行三态截图可辨）**：如果卡片只显示摘要文字、NG 不标色，就等于把"全链状态可见"这件事彻底弄丢了。这就是 UI-R06 验收②成为核心项的原因。（此处用词与 UI-R06 验收②的判据**同一套**，不得一处写"彩色"、一处写"三态可辨"——那会被读成两件事。）

**这条因果句证明的边界（务必写清，防止下一轮被换个问法问住）**

| 维度 | 结果区（单节点视图） | 画布卡片（全链） | 结论 |
|---|---|---|---|
| **状态可辨识性**（哪个节点 NG / 未运行 / 跑过） | 仅当前节点 | **全部节点，一屏看全** | **没丢** |
| **数值细节**（分数 / 面积 / 字符数 / 坐标） | 当前节点**完整** | 仅 `Compact` 一句（约 150 px 宽放不下更多） | **只保留"能判断要不要点进去"的量级**；要看细节点一下卡片（成本 ≈ 0） |

> **准确说法：丢掉的是"全链数值细节"，没丢的是"全链状态可辨识性"。**
> 这条边界必须留着，因为下一轮一定会有人换个问法：「**那我看不到别的节点的分数怎么办？**」—— 这**不是**同一个问题。标准答案是：点一下卡片即可（成本 ≈ 0），而"在 180 px 里同时给全 5 个节点的完整数值"本来就不成立，这正是 Q14 选单节点视图时**已经接受的取舍**。没有这句话，它就会被当成"分工还有缺口"，然后又绕回"要不要在结果区加列表"。

### 5.1.1 C5 的四条独立断言（逐条可测，缺一不算通过）

> 依据：Q14 已定案采用"**当前选中节点一行** + 展开明细"（非常驻列表，见 §6.1 Q14 附注）。主行替代了原来"一行 = 一个目标"的逐行语义，因此"点行 → 高亮对应目标"这条链路**必须被逐条钉死**，否则改版会悄悄削弱现网唯一的定位手段。

**适用范围（v1.5 收窄）：这一条不是"任何节点点了都必须高亮"，而是"点开过的节点必须高亮"。**

| 场景 | 要求 |
|---|---|
| 已点开过 / 已用「运行本节点」跑过的节点 | **C5-a ~ C5-d 四条全部成立**，缺一算失败 |
| **从未点开过**的节点（本次运行没有为它生成缩略帧） | 点行时**状态栏给出可行动提示**，例如"该节点本次运行未抓取缩略图，请先点『运行本节点』"；**不判失败**，但**不允许静默无反应**（否则退回到本次要治的"点了没效果"） |

**为什么这样界定（写进文档，防止以后被当成"实现偷懒"改回去）**：

- **缩略帧是按需生成的，不是每帧给所有节点都降采样。** 原因是性能硬约束：5 个节点每周期各做一次 5MP → 1/4 缩放约需 5~15 ms，会直接顶破 **16 ms** 的刷新预算（见 §5.3）。
- 因此"从未被点开过的节点没有缩略图"是**设计的必然结果，不是能力缺失**。
- **这不是降级，是把适用范围写准。** 若不写清，后果有两个，且第二个更糟：① QA 会在"从未点开"的场景按 C5 原字面测，判我们不通过；② 有人为了"修好验收"把按需生成改回"每帧全量降采样"，性能掉下来还以为是修好了 —— 这是拿 16 ms 预算换一条本来就不该存在的断言。

| 断言 | 操作 | 期望（唯一可接受的结果） | 判据 |
|---|---|---|---|
| **C5-a** | 一个有 3 个匹配目标的节点（**已点开过**，缩略帧已生成），**收起**状态下点它的主行 | 预览只高亮该节点**第 1 个**目标；第 2、3 个保持常态描边 | 高亮目标数 == 1 且序号 == 1；截图 + 高亮计数 |
| **C5-b** | 展开该节点，点明细第 **2** 条 | **前一目标（第 1 个）的高亮必须复原**，只第 2 个高亮 | 高亮目标数 == 1 且序号 == 2；**不允许出现 2 个同时高亮** |
| **C5-c** | 依次点明细 #3 → #2 → #1（每次等界面稳定；**同样要求已点开过**） | 每次都只有当前一条高亮，**无残留叠加**（不是"越点越多"） | 3 次点击后，每次高亮目标数恒为 1、序号分别 3/2/1 |
| **C5-d** | **选中**一个**无结果**的节点（"尚未运行"/"结果为空"，结果区显示其空态，**无主行可点**） | **清除高亮的动作必须挂在"选中该节点"这个事件上，不能等用户点主行**（空态下没有主行可点）；选中后预览**立即**清除所有高亮，**不弹异常、不写错误日志、不卡顿**；再点回有结果的节点能正常高亮 | **从"有高亮"切到某未运行节点后，立即无高亮**（此为主判据）；异常计数 == 0；日志无错误级记录；往返一次后行为与 C5-a 一致。**注：不用"往返一次后一致"当唯一判据 —— 它会掩盖"没清但也没报错"这种半失效（用户切到未运行节点，图上还亮着上一个节点的框）。** |

> **关于"点画布结果框反向定位结果行"（条件项 → 已关闭，不作为验收项）**：**架构师已核代码确认：现网确实没有该功能**（结果面板只有一个单向的"选中图形"事件，全库无反向接口）。因此：
> - **本期不新增反向定位**（不借改版之机扩大范围），C5 只覆盖 a~d 四条，**不留悬空条款**。
> - 如未来确实需要"画布 → 结果行"的反向联动，由主理人另立需求、单独编号，不塞进 C5 当隐身条款。
> - 保留一条通行原则：**不允许把没验证过的既有交互写成验收项** —— 那会变成一条永远没人测的条款，比漏测更危险，因为它让"验收全过"变成假信号。

### 5.2 交互一致性（与既有行为的对齐）

- "点行高亮预览"是现网唯一的"结果 → 图"定位手段，**改版必须保留且只能增强**（见 C5 / §5.1.1 四条断言）。明细行是新增的目标级入口，主行保留原有"选节点 + 高亮首个目标"语义。
- 结果区不得出现"空表格"：三种状态必须可区分 —— **尚未运行**（灰字文案）/ **运行中**（进度感 + 上次结果淡显）/ **已有结果**（数值 + 时间戳）。切换节点时**不得**先清空再回填（视觉跳动），应直接替换为缓存内容。
- OCR 模板状态卡片沿用匹配类节点已建立的范式（就绪 / 未配置 / 失败 + 缩略图 + 数量 + 时间 + 重做/删除），**不新造一套视觉语言**。

### 5.3 性能与稳定性

| 项 | 目标值 |
|---|---|
| 打开字符模板库（≤ 200 张模板图） | 扫描完成 ≤ 800 ms，UI 不冻结（缩略图异步加载） |
| 加入一个字符模板（含落盘 + 回读校验） | ≤ 200 ms，期间界面可操作 |
| 单个字符模板文件体积 | ≤ 256 KB（超过即按"尺寸异常"提示，见 OCR-T09） |
| 结果区刷新（每帧） | 不产生全表重建导致的闪烁；单节点结果 ≤ 60 条时刷新 ≤ 16 ms |
| **缩略帧生成（C5 适用范围的前提）** | **按需生成**（节点被点开 / 执行「运行本节点」时），**不得**每帧为所有节点降采样：5 个节点每周期各做一次 5 MP → 1/4 缩放约 5~15 ms/节点，合计会顶破 16 ms 刷新预算。"从未点开过的节点暂无缩略图"是该约束的必然结果 |
| 切换节点回填结果 | ≤ 100 ms |
| 连续运行 8 小时 | 结果缓存不无限增长（每节点只留最近 1 次结果；图像仅留引用/缩略），内存无持续增长 |

### 5.4 可诊断性

- 模板侧三类失败必须**文案可区分且可行动**：目录不存在（→ 提供"创建目录"）/ 目录不可写（→ 提供"迁移"）/ 部分文件读取失败（→ 列出文件名 + 原因 + 可复制）。
- 禁止再次出现"静默吞掉"：任何一张模板图读取失败都必须计入"失败计数"并在界面某处可见。
- 结果侧必须能查到"这个数是哪个节点的第几个目标、哪一帧、什么时间"（结果区时间戳 + 明细序号 + 日志同源）。
- 所有新增文案为中文，且不出现"无此功能 / 未实现 / 错误码"这类无行动指引的表述。

### 5.5 显示适配

- 在 Windows 缩放 100% / 125% / 150% 三档下，右栏不得出现控件重叠、文字截断、分隔条不可拖。**已知风险**：现状结果区是固定 220 px 硬值，改版必须改为相对/可拖值，否则 150% 下 288 px 内容宽会进一步缩水（可能降至约 240 px），两行高的节点行需在此宽度下仍不折行错位。

### 5.6 「不再静默」清单（六处，逐处对应到具体可见提示）

> 主理人要求：不能只在 PRD 里写"要有提示"，必须每处都能指到**具体的提示位置、文案、触发条件**，设计评审时逐条对。下表即该清单；**任一处缺失 = 该需求未交付**。
>
> **导读（为什么漏一个分支比写错更贵）**：**空白在验收时表现为"没人测"，上线后表现为"点了没反应"。** 前者让你以为覆盖全了，后者让操作员以为软件坏了 —— 而两者都源自同一件事：**某个分支从来没被写成需求**。S4 就是这样一个例子（原本只写"追加/拒绝"两种结局，第三种"达到上限"不存在），是复核时从一句"第 7 份被拒"里倒查出来的。所以本清单的读法是：**先问"这件事一共有几种结局"，再看表里有几种。**

| # | 静默场景 | 现状 | 提示位置（必须） | 提示文案要点 | 归属 |
|---|---|---|---|---|---|
| S1 | **模板库为空** | 目录不存在时静默自动创建；节点摘要尾部追加一句"模板目录为空，仅做分割"，仍显示 OK | ① 参数区模板状态卡片 → 警示态；② 运行结果该节点状态 → **WARN（黄）**；③ 管理界面顶部 → "⚠ 字符模板库为空（0 个）" | "字符模板库为空，当前仅做字符分割、不输出文本。点『管理模板库…』添加字符" | OCR-T04 / Q19 |
| S2 | **单张模板图读取失败** | 异常被吞掉，无任何痕迹 | 管理界面底部失败清单（文件名 + 原因）；顶部计数"已加载 37 个 · **2 个读取失败**" | "bad_1.bmp：不是有效图像" / "x2.tif：0 字节" / "a.txt：扩展名不支持"，可「复制诊断信息」 | OCR-T04 |
| S3 | **全部文件读取失败** | 仍显示成"模板目录为空"（把"读不出来"误报成"没有"） | 管理界面顶部 + 参数区状态卡片 | "**37 个文件均读取失败**"（严禁出现"模板目录为空"字样） | OCR-T04 |
| S4 | **同标签入库：三种结局都要有交代**（Q10 定案）——**(a) 追加成功 / (b) 拒绝重复 / (c) 达到上限** | 现状无此路径；一旦实现成"直接写文件"就会静默覆盖。**原表只有 (a)(b) 两种结局，(c) 是空白** | 标签输入框旁即时提示 + 入库结果反馈（管理界面行内/顶部，非模态打断） | **(a) 追加（第 2~6 份）**："已存在 3 张样本，**将追加为第 4 张**"（预告后果，不只说"已存在"）→ 入库后数量 +1、列表该行张数刷新；**(b) 拒绝重复**（若某分支不允许重复时启用）："字符 `7` 已存在，请换标签或先删除原条目"；**(c) 达上限（第 7 份）**："该字符已有 6 份样本（PNG/BMP/TIF/TIFF/JPG/JPEG 各一份），已达上限；请先删除旧样本"——**把"为什么是 6"写进文案**，否则用户会以为是产品随手限制的，然后去"改成 10"，一改就破了"文件名即标签"规则。**共同不变项：任何情况下不得覆盖同名文件且无提示；被拒时磁盘零改动** | OCR-T06 / Q10 |
| S5 | **标签含非法字符** | 无 | 标签输入框旁即时提示（红字），「加入模板库」置灰 | "标签不能包含 \ / : * ? \" < > \|" | OCR-T06 |
| S6 | **切换节点结果被清空** | 选中节点瞬间表格清空，必须重跑才回填 | 结果区行内状态 | 有缓存 → 直接显示上次结果 + 灰字时间戳"10:22:31"；无缓存 → 明确空态"该节点尚未运行"。**不得**出现空白表格 | UI-R08 |

> **为什么"被拒路径"必须验到「不出现坏文件」这个粒度，而不是只数文件个数**：半成品的后果是**可观测**的 —— 目录里多出一个 0 字节 / 无法加载的图，**下次扫描就会以"读取失败"的形式报出来，正好命中 S2**。也就是说：**一个没有被回滚的失败路径，会在下一次变成一个看起来无关的 S2 缺陷** —— 它把一次已经发生的**写**失败，伪装成一次新的**读**失败，排查时会走错方向（人会去查磁盘、查权限、查图源，而真因是半年前的某次写入没回滚）。这就是"零残留"不是洁癖的原因。

> 另有一组"点了没效果"归入同一治理口径（不新增编号，详见 **UI-R11**）：本期已把 **5 个**此类控件统一置灰 + tooltip —— 「框选 ROI」「预览矫正图」`RoiAngle` `FollowPose`（归 v3 T04 启用）与「显示合并字符串框」（归本期 T07 启用）。**判定标准一致：界面上存在的可交互控件，要么有可见效果，要么明确告知不可用（且说明"待何时启用"）。**



### 5.7 与在施需求的并行约束

- 本文 UI-R01/R02 改的是右栏容器与结果区，v3 的 T04 会在参数区新增"框选 ROI / 预览矫正图"等控件：**参数区分组结构须一次预留到位**，避免 T04 落地后再次重排（见 Q16）。
- 本文 OCR-T01/T02 与 v3 的 T03（OCR 字符框/结果标注）在"字符框"上有重叠：本文明确定义 **框的语义归 T03、框的数据与显示开关归本文 R07**，实现时以一侧为准、不得两套并行。

## 6. 待确认问题

| # | 问题 | 我的建议倾向（已于 v1.1 定案） |
|---|---|---|
| **Q10** | **同一字符标签允许多份样本吗？**（现场常见：同一字符有不同字体/污损/倾斜，多样本通常能提升识别率；但现加载规则是"一个文件 = 一个条目"，多样本是否被算法当作同类尚未确认。） | 建议**允许**，列表按标签归组显示"N 张"，入库时若标签已存在则提示"已存在 3 张样本，将追加为第 4 张"（用户可取消）。**若架构确认算法库不支持同类多样本，本期降级为"拒绝重复并提示"**——但无论哪种，都必须有可见提示，不允许静默覆盖同名文件。请架构给结论。 |
| **Q11** | **字符模板库是"全局共享文件夹"还是"节点私有"？** 现状是一个节点一个 `TemplateDir` 参数、多个节点可指向同一目录（共享）。 | 建议**保持共享文件夹语义**（兼容成本最低、用户已经这么用了）。管理界面增加一行只读提示"该目录当前被本流程 2 个节点引用"，让"改一处影响两处"变得可见，而不是改成节点私有隔离。 |

| **Q18** | **"从运行结果一键入库"（OCR-T07）本期是否必须？** 它对现场调错最有价值，但依赖预览图上的字符框可交互，而字符框的交互归 v3 的 T03。 | 建议 **P1、排在 T03 之后**：若 T03 按期交付则一并做；若 T03 延期，本期只做 T01/T02（从图框选入库已能覆盖主要场景），T07 顺延，不做半成品。 |
| **Q19** | **OCR 模板库为空时，节点状态该显示什么？** 现状是"仅做分割"却仍显示 OK —— 用户看到 OK 会误以为识别成功。 | 建议改为 **WARN（黄）**，文案"模板库为空，仅分割未识别"，且**不阻断流程**（下游仍可继续）。理由：OK 是"检测通过"的语义，把它用在"根本没识别"上会直接导致误判良品，这属于风险而不是提示偏好。 |

**跨文档影响标记 `⟶架构`（v1.8 起生效，v1.9 补规则与历史索引）**

用途：把"哪几版 PRD 变更影响了架构文档"变成**可定向核查**的索引，架构侧按章节号直接跳转，不必逐版全文 diff。它不依赖消息是否送达，是本 PRD 与架构文档之间唯一的防滞后机制。

**使用规则（两条，缺一即退化为装饰）**

1. **只标"改变了架构文档内容或验收口径"的版本**。纯措辞润色、编号调整、错别字**不标** —— 否则每版都有标记，等于没有标记。
2. **标记必须带架构文档的章节号**，便于直接跳转核对，不用先搜"这条落在哪"。
