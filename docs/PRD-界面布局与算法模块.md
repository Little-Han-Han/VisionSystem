## 2. 产品目标

**一句话目标**：把 VisionSystem 主界面改造成"一眼可读"的工业 HMI（良品率 / OK-NG / 运行控制成为视觉焦点），同时把流程编排补齐为覆盖「取图 → 定位 → 位置修正 → 检测/量测 → 判定」的完整算法工具链，并让**每个节点的中间处理效果在流程界面内实时可见**。

| 编号 | 目标 | 衡量方式（可验证） |
| --- | --- | --- |
| **G1** | 工程软件视觉达标：统一深色工业主题，信息分区清晰，主视线聚焦于"良品率 + OK/NG + 运行控制" | 在 1440×900 基准分辨率下，OK/NG 徽标、统计区、运行控制三组元素全部位于右栏视觉热区，且块高分别 ≥ 88 / ≥ 150 / ≥ 56 布局像素 |
| **G2** | 算法工具链完整可用：补齐**位置修正、直线卡尺、圆卡尺、模板匹配（NCC）**，完善**图像采集**与 **Blob 分析**，每个节点都有可配置参数面板 | 工具箱中可用节点 ≥ 12 个，其中带参数面板的节点 ≥ 11 个 |
| **G3** | 中间结果实时可视：流程界面内嵌图像预览，**选中哪个节点就显示哪个节点的输出**；单步 / 单帧 / 连续运行均能实时刷新 | 「单步运行」时每个节点执行后预览区立即刷新出该节点输出帧 + 该节点叠加图形 |
| **G4** | 判定闭环：检测/量测节点均可设上下限并参与 OK/NG 汇总，主界面与流程界面结论一致 | 任一节点判定失败 → 流程结论 NG、主界面徽标 NG、日志输出失败项名，三者一致 |
| **G5** | 合规增量：零第三方依赖；沿用既有坐标、序列化、构建约定；旧配置可平滑升级 | `VisionPlatform.csproj` 无新增 PackageReference；旧 `appconfig.json` 加载后旧流程仍可打开并运行 |

### 范围外（本期不做）

- 多分支 / 并行流程拓扑（仍为**单链**）；
- 海康真实相机 SDK 联调；
- 视觉标定（像素当量 / 手眼标定）；
- 图标资源、皮肤换肤系统、第三方 UI 库。

#### 4.2.3 位置修正（新增模块）

> **默认假设 B（输入输出语义）**：
> - **基准来源** `RefSource`：`Auto`（取上游**最近一个**匹配类节点——形状匹配 / 模板匹配——的第 1 个结果作为实时对照基准）或 `Manual`（手动指定 `RefX/RefY/RefAngle`，即"示教一次"记录标准位姿）。
> - **输入**：实时测得位姿 `(Cx, Cy, Angle, Scale)` + 基准位姿 `(Rx, Ry, Ra)`。
> - **输出**：`dX = Cx - Rx`、`dY = Cy - Ry`、`dAngle = Angle - Ra`（度）、`dScale = Scale`，写入**运行时变换上下文**（下文统称 `RunTransform`）。
> - **下游消费规则**：位置修正节点之后的所有带 ROI 节点，执行前把自身 ROI **先绕基准点 `(Rx,Ry)` 旋转 `dAngle`，再平移 `(dX,dY)`** 得到实际 ROI；`EnableAngle=0` 时只平移不旋转。本期为单链，故不存在"谁被修正"的歧义；上游节点不受影响。
> - **多个位置修正节点**：以**最后一个生效的**为准（覆盖式），不做累加。

| ID | 需求描述 | 优先级 | 验收标准 |
| --- | --- | --- | --- |
| **FR-ALG-08** | 新增节点类型 `PositionCorrect`（工具箱显示名「位置修正」），按假设 B 计算 `dX/dY/dAngle/dScale` 并写入 `RunTransform` | P0 | ①上游为形状匹配时，人为平移/旋转工件后，输出 `dX/dY` 与实际像素位移误差 ≤ 2 px、`dAngle` 误差 ≤ 0.5°；②`RefSource=Auto` 且上游无定位结果时摘要给出"位置修正：上游无可用定位结果"并判 NG |
| **FR-ALG-09** | `RunTransform` 在 `FlowRunner` 中传递，下游带 ROI 节点（形状匹配 / 模板匹配 / Blob / 直线卡尺 / 圆卡尺 / 预处理 / 清晰度 / 拟合）在使用 ROI 前统一应用该变换 | P0 | ①构造"图像源 → 形状匹配 → 位置修正 → Blob"链，整体平移 (40, 25) 后 Blob 仍能命中且数量一致、面积差异 ≤ 5% |

#### 4.2.6 实时显示（流程界面）

> **默认假设 D（"实时显示"粒度）**：取 **(b) 逐节点粒度**——每个节点执行后立即把该节点的输出帧 + 该节点产出的叠加图形刷新到流程界面预览区，并支持**选中节点回看**该节点最近一次输出。分级：
> - **P0**：流程界面内嵌预览区 + 「单步运行」逐节点刷新 + 「运行（单帧）」结束后显示选定/末节点结果；
> - **P1**：「连续运行」周期性刷新（覆盖式投递，限帧 ≤ 30 fps）+ 画布节点执行状态与耗时标注；
> - **P2**：预览显示模式切换与"暂停自动刷新"开关。
>
> 理由：用户原话"流程图界面要能够实时显示图像处理的效果"要求的正是**中间过程可见**，仅显示最终结果无法支撑调参。

## 6. 约束（必须遵守）

| # | 约束 | 说明 |
| --- | --- | --- |
| C1 | **零第三方依赖** | 控件库与平台层不得引入任何 NuGet 第三方 UI 库；"醒目"一律由字号 / 颜色 / 区块 / 留白实现，不使用图标素材 |
| C2 | **构建与文件登记** | 构建走根目录 `build.bat`（MSBuild，Debug/Release x64）；C++ 新增 `.h/.cpp` 必须同时登记 `VisionAlgo.Native.vcxproj` 与 `.vcxproj.filters`；C# 新增 `.cs` 必须登记 `VisionPlatform.csproj`（传统 csproj 不自动包含） |
| C3 | **配置向下兼容** | 流程配置持久化在 `AppConfig.Flows`（`[DataContract]` 序列化）；新增节点类型采用**新字符串 Type**追加，旧流程不得因未知类型而加载失败；`FlowSettings.SchemaVersion` 升级时提供迁移或容错默认值 |
| C4 | **坐标约定** | 图形几何属性用**图像坐标**；线宽 / 手柄 / 容差用**屏幕像素**。卡尺 ROI 属几何属性 → 图像坐标；卡尺投影窗口线宽 → 屏幕像素 |
| C5 | **相机 Id 前缀** | `USB-`（本机）/ `SIM`（模拟）/ `HIK`（海康）；新增图像源数据源时不得破坏该前缀约定 |
| C6 | **单链拓扑限制** | `FlowRunner` 本期仍只允许单链（多入/多出/成环报错）。位置修正的变换传递基于单链语义；若后续放开分支需重新定义作用域 |
| C7 | **线程与内存** | 连续运行不得阻塞 UI 线程；帧采用覆盖式投递（旧帧立即释放）；`Bitmap` 所有权沿用现有 `FlowOutputEventArgs` 的移交约定，避免双释放与泄漏 |
| C8 | **色弱友好补充** | 颜色语义除绿/红外，须有**文本兜底**（`OK`/`NG` 字面文字），不得仅靠颜色表达结论 |
