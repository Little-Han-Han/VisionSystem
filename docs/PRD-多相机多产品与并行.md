## 1. 产品目标（增量）

**一句话目标**：让 VisionSystem 从"一次跑一条流程的单工位工具"升级为"一套软件同时管理**多个相机、多个产品、多条并行流程**，且每条流程在界面上**可分辨、可追溯**"。

| 编号 | 目标 | 衡量方式（可验证） |
| --- | --- | --- |
| **G6** | **多相机并行取流**：多个相机可同时打开、同时取流，并分别显示到不同视图 | 2×2 布局下 4 个视图绑定 4 个不同相机（SIM / USB 可混用）同时连续取流，各视图独立刷新、互不串图 |
| **G7** | **多产品建模与快速换型**：产品型号可配置、可切换，切换后只跑/只显示该产品下的流程 | 切换到产品 A 后，流程列表与画布只剩 A 的流程；切回"全部"恢复完整列表；切换动作 ≤ 1 次点击 |
| **G8** | **多流程并行执行**：N 条流程各自独立线程 + 独立算法上下文同时运行，互不串扰 | 3 条流程绑定 3 个相机同时运行：各自出独立结论；其中 1 条取帧失败被中止，其余 2 条继续运行不受影响 |
| **G9** | **可观测**：界面处处能看出"这是哪条流程 / 哪个产品 / 哪个相机"，日志分级且可按流程过滤 | 视图标题条、状态栏、右栏运行列表、日志行首**四处**均带流程名；日志可按流程与级别过滤并导出 |
| **G10** | **合规增量**：不推翻"单流程内部单链"约束，零第三方依赖，旧配置可平滑升级 | `FlowRunner.TryBuildChain` 单链校验逻辑不变；`csproj` 无新增包；旧 `appconfig.json` 加载后旧流程 Product="" / Enabled=true 且可正常运行 |

### 范围外（本轮不做）

- **单流程内部分支并行**（方案②）：需重写拓扑解析与 ROI/变换作用域，与既有单链约束冲突，本期不做（见 §6 冲突点 C-1）；
- 相机硬件同步触发（外触发 / 编码器同步）；
- 跨流程的结果关联（如"相机 A 定位结果传给相机 B 的流程"）；
- 分布式 / 多机部署。

## 3. 需求池

优先级：**P0** 必须（本增量核心，"能跑起来的最小闭环"）；**P1** 应该；**P2** 可选。

> 分级原则（按 team-lead 要求）：**P0 = 最小闭环**——多条流程可各自绑定相机并同时运行、各自出结论、界面能看出是哪条流程；**统计分产品、日志过滤导出、并行数配置**等一律 P1/P2。

### 3.3 流程并行（`FR-PAR-01` ~ `FR-PAR-10`）— 核心

> **默认假设 E（并行粒度）**：采用**方案①「多流程并行」**——N 条流程各自独立线程 + 独立 `FlowRunner` 实例（因而各自持有独立 `VisionAlgo` 原生上下文）同时运行；**每条流程内部仍是单链串行**，与既有单链约束不冲突。
> **方案②「单流程内分支并行」本期不做**（`FR-PAR-10`，P2，且需先解除单链约束）。
>
> 选中方案①的理由：①用户语境是"多个相机、多个产品"——即 A 相机跑 A 产品流程、B 相机跑 B 产品流程，同时跑，这正是"多流程并行"；②已落地的 `FlowRunSession` 会话模型（Begin/ExecuteNode/Finish + 节点游标）本身就是"一条流程一个执行实例"，并行只需在**流程维度**做实例隔离，改动可控；③方案②需重写拓扑解析、分支同步、以及位置修正 `RunTransform` 的作用域定义（分支各自修正还是共享？），代价与风险都显著更高。

| ID | 需求描述 | 优先级 | 验收标准 |
| --- | --- | --- | --- |
| **FR-PAR-01** | 执行模型定为**多流程并行**：每条流程一个执行线程 + 一个 `FlowRunner` 实例（独立 VisionAlgo 上下文）；流程内部按单链串行执行 | P0 | ①3 条流程分别绑定 3 个不同相机同时点"全部启动"，3 个视图**同时**产出结果；②每条流程的结论独立（1 条 NG 不会让另 2 条变 NG） |
| **FR-PAR-02** | 新增流程运行管理器（建议 `Flow/FlowRunManager.cs`，静态或单例）：统一 `StartAll / PauseAll / StopAll / StartOne(flowId) / StopOne(flowId)`，维护 `FlowId → 运行上下文（线程 + FlowRunner + 会话）` 映射与状态查询 | P0 | ①主界面"全部启动"启动所有 `Enabled=true` 且相机可用的流程；②"全部停止"停止所有；③查询接口能返回每条流程的 状态/最近结论/耗时/累计 |
| **FR-PAR-03** | 每条流程**独立取帧、独立会话**，互不共享 `FlowRunSession` 与算法上下文；单条流程致命错误（取帧失败/异常）只中止自己 | P0 | ①人为拔掉其中一条流程的相机 → 该流程中止并在日志 ERROR；②其余 2 条**继续运行**，帧率不受影响；③无跨流程异常抛出 |
| **FR-PAR-04** | 并行结果按 `ViewIndex` 分发到对应视图：`FlowOutputEventArgs` **新增 `FlowId` / `FlowName` / `Product` 字段**，发布时一并带上；`MainForm` 按 ViewIndex 路由、按 FlowName 更新标题条 | P0 | ①流程 A（ViewIndex=1）的结果只出现在视图 1，B（ViewIndex=2）只出现在视图 2，不串图；②标题条显示的流程名与实际运行的流程一致 |
| **FR-PAR-05** | 并行下界面可分辨：每个视图显示**自己的**结论（角标 + 标题条流程名 + 运行中标记）；右栏显示"运行中 n 条"以及**每流程一行**的状态 | P0 | ①3 条并行时右栏列出 3 行，各自含 流程名 / 相机 / 状态 / 最近结论 / 耗时；②停止其中 1 条后该行状态变"已停"，其余不变 |
| **FR-PAR-06** | 最大并行数限制：配置项 `MaxParallelFlows`，**默认 4**，可调 1~8；达到上限时**拒绝启动**并给出中文提示（**不排队**，避免"何时才跑"的不确定性） | P1 | ①设为 1 时启动第 2 条 → 拒绝并提示"已达最大并行数 1，请先停止其它流程"；②设为 4 时第 5 条被拒绝；③配置持久化 |
| **FR-PAR-07** | **单条流程独立启停**：主界面流程运行列表每行提供"启动 / 停止"两个纯文字按钮（或在流程界面底部对当前流程启停），不影响其它流程 | P1 | ①3 条运行中，停止第 2 条 → 另 2 条继续；②再单独启动第 2 条 → 恢复运行 |
| **FR-PAR-08** | 并行线程安全：`FlowOutputChannel` 发布与统计计数加锁；UI 更新一律 `BeginInvoke` 回 UI 线程；关闭主窗体 / 流程窗体时**先停所有流程再 Join**（沿用现有 FlowForm 关窗 Join 的经验） | P1 | ①3 条并行连续运行 5 分钟：无异常、无跨线程控件访问异常、内存增长 ≤ 50 MB；②点关闭窗口后 ≤ 3 s 内安全退出，无"集合已修改"类异常 |
| **FR-PAR-09** | 并行性能节流：每条流程独立限帧（默认 ≤ 30 fps，覆盖式投递旧帧立即释放）；连续运行时 `CaptureFrames=false`（不逐节点存帧，省内存） | P1 | ①3 条并行时主界面仍可正常拖动/点击，无卡死；②连续运行 5 分钟内存增长 ≤ 50 MB |
| **FR-PAR-10** | （P2 / 本期不做）**单流程内分支并行**：一个流程内部多分支同时执行 | P2 | 前置条件：先解除"单链拓扑"约束、定义分支同步点与 `RunTransform` 作用域。本期仅登记需求，不排期 |
