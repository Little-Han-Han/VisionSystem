│     └ RecipePanel  配方增删改查                                 │
└──────────────────────────────────────────────────────────────┘
             │                                  │
             ▼                                  ▼
┌────────────────────────────┐   ┌──────────────────────────────┐
│  业务层                     │   │  显示控件库                    │
│  Vision/   InspectionEngine │   │  VisionSystem.Controls         │
│  Recipe/   Recipe + Store   │   │    ImageViewer / 几何图形      │
│  Camera/   CameraManager    │   │    Viewport / CvInterop        │
│  Communication/ TCP·Modbus  │   └──────────────────────────────┘
│  Models/   User             │
└────────────────────────────┘
             │
             ▼
┌──────────────────────────────────────────────────────────────┐
│  P/Invoke 边界   Native/VisionAlgo.cs（DllImport + 结构体映射） │
└──────────────────────────────────────────────────────────────┘
             │
             ▼
┌──────────────────────────────────────────────────────────────┐
│  算法层  VisionAlgo.Native.dll（C++ / OpenCV 4.5.5）           │

**分层原则**：界面不直接碰算法，算法不认识界面。中间靠 `Native/VisionAlgo.cs` 这道唯一的 P/Invoke 边界隔离。

### 界面全部采用 Designer 模式

每个窗体拆成两个文件：

| 文件 | 内容 |
|---|---|
| `XxxForm.cs` | 业务逻辑、事件处理 |
| `XxxForm.Designer.cs` | `InitializeComponent()`，纯布局 |

在 VS 中双击 `.cs` 即可打开设计器，直接拖拽调整控件位置与大小，
改完保存后逻辑代码不受影响。`ImageViewer` 是自定义控件，在构造函数中
创建后 `SetChildIndex(viewer, 0)` 放入容器（保证 Fill 生效）。

### 依赖统一放 ThirdParty

所有第三方 DLL 按用途放在 `ThirdParty/<用途>/` 下，项目通过**相对路径**引用，
不使用绝对路径、不依赖系统 PATH，整个仓库拷到别的机器仍可直接构建。

## 4. 模块职责

### Core
- `Logger`：写文件 + `Logged` 事件推给界面（主窗体底部日志订阅它）。
- `AppPaths`：`%AppData%\VisionPlatform` 下的配方、日志、配置路径。
- `Json`：基于 `DataContractJsonSerializer`，带简易缩进整理。
- `OpResult` / `OpResult<T>`：统一的成功标志 + 消息，避免到处抛异常。

### Native（关键层）
`VisionAlgo.cs` 是**唯一**接触 C++ 的地方：
- 结构体一一对应 C 端（`VA_Image`、`VA_Blob`…），`LayoutKind.Sequential`。
- 调用约定 `StdCall`；C 端导出用 `__stdcall`（x64 下被忽略，但保持一致）。
- `Bitmap.LockBits` 后把 `Scan0` 直接交给 C++，**零拷贝**传入。
- 输出缓冲区由 C# 分配（8bpp 灰度 + 灰度调色板），C++ 只写 `data`。

### Camera
- `ICamera`：统一契约（Open/Close/StartGrab/StopGrab/GrabOne + 帧事件）。
- `SimCamera`：合成图像源，无硬件也能跑通全流程。
- `HikCamera`：海康适配器（**当前为占位实现，见遗留问题**）。
- `CameraManager`：枚举、打开、维护 `Current`。

### Communication
- `TcpClientSession` / `TcpServerSession`：后台线程收，事件抛（界面侧 `BeginInvoke`）。
- `ModbusTcpClient`：自己实现 MBAP + PDU，支持 0x03 / 0x06 / 0x10。

### Recipe
`Recipe` 聚合相机 Id、检测参数、通讯目标；`RecipeStore` 负责 JSON 存取与"当前配方"切换（切换会广播 `CurrentChanged`，算法面板自动同步参数）。

### Vision
`InspectionEngine` 编排：预处理 → 清晰度 / Blob / 模板 / 圆拟合 → 汇总 OK/NG。**算法本体在 C++，这里只有流程和判定**。

### UI

| 窗体 | 职责 |
|---|---|
| `MainForm` | **主运行界面**：多显示视图（1 / 2 / 4）、循环运行 / 暂停 / 停止、单帧与同步采集、数据统计（总数 / OK / NG / 良率 / 节拍）、运行日志 |
| `CameraForm` | 相机管理：枚举、打开 / 关闭、连续采集、单帧、实时预览 |
| `AlgoForm` | 算法参数编辑 + 离线测试（**支持打开本地图片**，无需相机） |
| `CommForm` | TCP 客户端 / 服务端 / Modbus TCP 收发测试 |
| `RecipeForm` | 配方增删改查 |
| `LoginForm` / `SplashForm` | 登录 / 启动加载 |

**多相机与同步拍摄**：`CameraManager` 维护多个已打开相机（`OpenedCameras`）。
主界面的「同步采集」先把所有相机的帧**一次性取到手**（尽量缩短相机之间的时间差），
再逐路显示与检测，并按打开顺序分配到各个视图；
视图数量不足时，多余的图像会被正确释放，不会泄漏。

## 5. C++ ↔ C# 调用规范

这是整套架构最容易出错的地方，约定如下：

1. **导出形式**：`extern "C" __declspec(dllexport) __stdcall`，避免名称修饰与调用约定不匹配。
2. **图像传递**：`VA_Image{data, width, height, channels, stride}` 直接描述 `cv::Mat` 内存布局，C# 侧 `LockBits` 后零拷贝。
3. **内存归属**：**谁分配谁释放**。输出缓冲区一律由 C# 分配并填好尺寸，C++ 只写内容，绝不跨模块 `new`/`delete`。
4. **错误处理**：函数返回错误码，详细文本通过 `va_get_last_error` 取回，C++ 内部捕获所有异常。
5. **上下文句柄**：`va_create` / `va_destroy`，模板训练状态存在句柄里，天然支持多实例。

新增一个算法的完整步骤见第 7 节。

## 6. 一次检测的数据流

```
相机（SimCamera / HikCamera）
   │  GrabOne() → Bitmap（BGR）
   ▼
InspectionEngine.Run(frame, cfg)
   │
   ├─ ① VisionAlgo.Preprocess  → C++ 灰度化/模糊/二值化/形态学 → 8bpp 灰度图
   ├─ ② Sharpness / AnalyzeBlobs / MatchTemplate / FitCircle（按开关）
   │      每项都把结果结构与消息塞进 InspectionResult
   └─ ③ 判定 OK/NG，汇总耗时与失败原因
   ▼
AlgoPanel.ShowResult()
   ├─ 灰度图送 ImageViewer 显示
   ├─ Blob → CircleShape、拟合圆 → CircleShape、匹配框 → RectangleShape
   │      （复用 VisionSystem.Controls 的图形系统，可继续用鼠标编辑）
   └─ OK/NG 大字 + 明细列表
```

## 7. 扩展指南

### 加一个算法（例：边缘缺陷检测）
1. `vision_algo.h` 增加导出函数与结果结构体（C 风格）。
2. `vision_algo.cpp` 用 OpenCV 实现，异常转错误码。
3. `Native/VisionAlgo.cs` 加 `DllImport` 声明 + 一个返回 `OpResult<T>` 的托管方法（样板可照抄 `FitCircle`）。
4. 需要进流程就在 `InspectionConfig` 加开关/阈值，在 `InspectionEngine.Run` 加一段。
5. 界面：算法面板加控件，`ShowResult` 加图形叠加。

### 加一种相机
实现 `ICamera`（照抄 `SimCamera` 的结构），在 `CameraManager.CreateById` 里登记前缀即可，其余层不用改。

### 加一种通讯协议
在 `Communication/` 下新增类，界面在 `CommPanel` 加一个 `GroupBox`。

## 8. 构建

```bat
build.bat            :: Debug|x64
build.bat Release    :: Release|x64
```

产物：
- `bin\x64\{配置}\VisionAlgo.Native.dll` + `opencv_world455*.dll`
- `src\VisionPlatform\bin\{配置}\VisionPlatform.exe`（PostBuild 会把上面两个 DLL 复制过来）

打开 `VisionSystem.sln`（**唯一解决方案**）即可在 VS2022 中开发全部四个项目。

> 构建脚本会先清空 `http_proxy` 等环境变量：宿主 shell 可能同时注入大小写不同的
> 代理变量，会让 MSBuild 的 CL 任务抛"已添加项"异常。
