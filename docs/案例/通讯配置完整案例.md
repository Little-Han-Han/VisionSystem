# 通讯配置完整案例：双相机双流程 + 心跳 + Ready/Busy + 组合结果

> 目标：用一个可运行的案例，把「点位 → 消息 → 任务 → 流程绑定」串起来。
> 场景：一台设备有 **两个相机、两条流程**（`F1` 上相机、`F2` 下相机）。
> 上位机/PLC 发 `TRIG` 触发两条流程；两条流程都出结果后，软件把组合结果发给 MES，
> 等 MES 回 `ACK`，再恢复 `Ready`。期间每 1 秒发一次心跳。
>
> 配套文件：
> - 示例配置：[通讯配置-双流程-TCP示例.json](通讯配置-双流程-TCP示例.json)
> - TCP 模拟器：[tcp_mes_sim.py](tcp_mes_sim.py)

---

## 1. 先理解四个概念

| 概念 | 作用 | 本案例中的例子 |
|---|---|---|
| **端点 Endpoint** | 一条物理/逻辑连接：TCP 客户端、TCP 服务端、Modbus TCP、OPC UA… | `SIM-PLC`（TCP 服务端，监听 9000） |
| **点位 Point** | 给协议地址起名字，流程/任务只认名字 | `Line.Trigger`、`Line.Ready`、`Flow1.Busy` |
| **消息 Message** | 一条要发送的报文，支持占位符 | `ResultJson`：`{"f1":"{Flow1.Passed}",...}` |
| **任务 Job** | 常驻逻辑：心跳、触发、等结果、发消息、等 ACK | `Heartbeat`、`Trigger`、`Result` |

---

## 2. 场景信号表

| 点位名 | 方向 | 类型 | 说明 |
|---|---|---|---|
| `Line.Trigger` | Read | String | 收到包含 `TRIG` 的文本即触发 |
| `Line.Ack` | Read | String | 收到包含 `ACK` 的文本表示 MES 已收 |
| `Line.Ready` / `Line.Busy` / `Line.Fault` | Write | String | **工位级**握手：可接料 / 检测中 / 故障 |
| `Flow1.Ready` / `Flow1.Busy` / `Flow1.Fault` | Write | String | **流程 1** 真实运行状态（自动绑定） |
| `Flow2.Ready` / `Flow2.Busy` / `Flow2.Fault` | Write | String | **流程 2** 真实运行状态（自动绑定） |
| `Line.Heartbeat` | Write | String | 每秒翻转一次，证明软件在线 |

> 为什么分两套：`FlowBindings` 会每 100ms 按流程真实状态写 `Flow*.Busy/Ready`；
> 结果任务用 `Line.Busy/Ready` 做工位握手。两者混用会互相覆盖（流程跑完自动 Ready，
> 但 MES 还没 ACK），现场会出现“Ready 提前置位”。

> 真实 PLC 用 Modbus 时把 String 换成 Bool、地址换成 `HR:100` 这类即可，见 §7。

---

## 3. 配置步骤（在软件里点）

1. 打开「通讯」界面；
2. 新建端点 `SIM-PLC`：
   - 类型：**TCP 服务端**
   - 端口：`9000`
   - 启用 + 启动时自动连接
3. 点左下角 **「点位/任务…」**，进入配置窗体；
4. **点位**页：按 §2 表格新增 12 个点位（端点都选 `SIM-PLC`，地址留空，类型 String）；
   - 方向：Trigger/Ack 选 `Read`，Ready/Busy/Fault/Heartbeat 选 `Write`；
5. **消息**页：新增 `ResultJson`
   - 端点 `SIM-PLC`，模式 `Text`
   - 模板：
     ```json
     {"line":"L1","f1":"{Flow1.Passed}","f2":"{Flow2.Passed}","yield":"{Yield}","time":"{Time}"}
     ```
   - 结束符：`\r\n`
6. **任务**页：新增 4 个任务（见 §4）；
7. **流程信号**页：为 `F1`、`F2` 各配一行 Busy/Ready/Fault（见 §5）；
8. 保存。

> 下拉里没有刚建的流程/点位时，点「刷新下拉」；保存也会自动重载。

---

## 4. 四个任务

### 4.1 启动初始化

| 字段 | 值 |
|---|---|
| 触发 | `Startup` |
| 动作 | `SetPoint:Line.Ready=true`、`SetPoint:Line.Busy=false`、`SetPoint:Line.Fault=false` |

软件启动后先把工位置为 Ready，避免 PLC 等到第一条结果才认为可接料。

### 4.2 心跳（每 1 秒）

| 字段 | 值 |
|---|---|
| 触发 | `Timer` |
| 周期 | `1000` |
| 动作 | `SetPoint:Line.Heartbeat=toggle` |

`toggle` 会让点位在 true/false 之间翻转，PLC 侧看到稳定方波即认为软件在线。

### 4.3 触发启动（PLC 发 TRIG）

| 字段 | 值 |
|---|---|
| 触发 | `PointEdge` |
| 触发点位 | `Line.Trigger` |
| 期望值 | `TRIG` |
| 动作 | `StartFlow:F1`、`StartFlow:F2` |

上升沿触发，不会因为文本一直是 `TRIG` 而反复启动；收到 `ACK` 后点位值变化，下一次 `TRIG` 才会再次触发。

### 4.4 组合结果（F1+F2 都出结果才发）

| 字段 | 值 |
|---|---|
| 触发 | `ResultGroup` |
| 流程 | `F1`、`F2`（双击「流程」列勾选） |
| 模式 | `AllFresh` |
| 窗口 | `1500` ms |
| 动作 | 见下 |

```
SetPoint:Line.Busy=true
SetPoint:Line.Ready=false
SendMessage:ResultJson
WaitPoint:Line.Ack=ACK@5000
SetPoint:Line.Busy=false
SetPoint:Line.Ready=true
```

- `AllFresh`：两条流程的结果都在 1.5 秒窗口内到齐才发送，避免拿 F2 的新结果配 F1 的旧结果；
- 动作按顺序执行；`WaitPoint` 超时即任务失败，`LastError` 可在「诊断」页看到；
- 生产环境建议加 `ContinueOnError` 或在最后统一复位，避免一直停在 Busy。

## 5. 流程信号绑定（每条流程一份）

| 流程 | 端点 | Busy | Ready | Fault |
|---|---|---|---|---|
| `F1` | `SIM-PLC` | `Flow1.Busy` | `Flow1.Ready` | `Flow1.Fault` |
| `F2` | `SIM-PLC` | `Flow2.Busy` | `Flow2.Ready` | `Flow2.Fault` |

任务引擎每 100ms 检查 `FlowRunManager`：

- `Starting / Running / Paused / Stopping` → Busy=true、Ready=false；
- `Idle` 且流程启用 → Busy=false、Ready=true；
- `Faulted` → Fault=true、Ready=false；
- 写入失败会保留旧状态并每 100ms 重试，断线恢复后自动补发。

---

## 6. 运行案例（无需真实 PLC）

1. 启动软件，确认 `SIM-PLC` 显示「监听中」；
2. 确保 `F1`、`F2` 两条流程存在且能单独运行（可用模拟相机 `SIM-0` 或本地图片）；
3. 运行模拟器：

```bat
python docs\案例\tcp_mes_sim.py
```

4. 模拟器每 5 秒发一次 `TRIG`；软件收到后启动两条流程；
5. 两条流程出结果后，模拟器收到：

```json
{"line":"L1","f1":"true","f2":"false","yield":"97.50","time":"14:32:10"}
```

6. 模拟器自动回 `ACK`；软件把 Busy 置 false、Ready 置 true，等待下一次触发。

### 预期信号时序

```text
MES/PLC           软件                         F1/F2
  │  TRIG           │                             │
  ├────────────────>│ StartFlow F1,F2             │
  │                 ├────────────────────────────>│
  │                 │ Busy1=true, Busy2=true      │
  │<────────────────┤                             │
  │                 │        结果 OK / NG          │
  │                 │<────────────────────────────┤
  │                 │ AllFresh 到齐 → ResultJson  │
  │<────────────────┤                             │
  │  ACK            │                             │
  ├────────────────>│ WaitPoint 成功               │
  │                 │ Busy=false, Ready=true      │
  │<────────────────┤                             │
```

## 7. 换成真实 PLC（Modbus TCP）

把 `SIM-PLC` 换成 Modbus 端点即可，点位名不变：

| 点位 | Modbus 地址 | 类型 | 方向 |
|---|---|---|---|
| `Line.Trigger` | `HR:100` | Bool | Read |
| `Line.Ack` | `HR:101` | Bool | Read |
| `Line.Ready` / `Line.Busy` / `Line.Fault` | `HR:110 / 111 / 112` | Bool | Write |
| `Flow1.Ready` / `Flow1.Busy` / `Flow1.Fault` | `HR:120 / 121 / 122` | Bool | Write |
| `Flow2.Ready` / `Flow2.Busy` / `Flow2.Fault` | `HR:130 / 131 / 132` | Bool | Write |
| `Line.Heartbeat` | `HR:140` | Bool | Write |

注意：

- 当前 Modbus 驱动只支持 `HR / IR` 寄存器，`CO / DI` 会明确报错；
- 组合结果建议仍走 TCP/JSON 发给 MES（Modbus 写字符串/多寄存器需要额外约定）；
- 需要数值型结果时，在流程里加「脚本」节点计算，再 `SetPoint` 写数值点位。

---

## 8. 多相机多流程要点

1. **一条流程一份 Busy/Ready/Fault**：不要两条流程共用一个 Busy，否则上位机分不清是谁在忙；
   工位握手（Line.Busy/Ready）与流程状态（Flow*.Busy/Ready）分开，避免自动状态覆盖握手；
2. **组合任务用流程 Id 列表**：`F1;F2` 放在同一个 `ResultGroup`，`AllFresh` 保证同批；
3. **触发按需启动**：`StartFlow` 可以只启动相关流程，不必「全部启动」；
4. **心跳独立于流程**：流程停止时心跳仍继续，PLC 才知道软件没死；
5. **主界面日志过滤**：工具栏「日志」下拉可切 `实拍 / 模拟 / 仅异常 / 全部`，
   只影响显示，文件与日志库仍记录全部。

## 9. 排查清单

| 现象 | 先查 |
|---|---|
| 收不到 `TRIG` | 端点是否「监听中」；模拟器是否连上 9000；点位方向是否 Read |
| 触发了但流程没跑 | `F1/F2` 是否启用、是否绑定可用相机；「诊断」页任务 LastError |
| 结果不发 | 两条流程是否都出结果；`AllFresh` 窗口是否太短；`ResultJson` 是否绑定端点 |
| 一直 Busy | `WaitPoint Line.Ack` 是否超时；模拟器是否回 `ACK`；查看任务 LastError |
| Ready 不恢复 | 流程是否 Faulted；Fault 点位是否被置 true；先清故障再重启流程 |
| 改了点位下拉没有 | 点「刷新下拉」，或保存后自动重载 |

## 10. 合并到现有配置（不要整文件覆盖）

配置文件在**程序目录**，不是 `%AppData%`：

```text
bin\x64\Release\appconfig.json     ← 现场 Release 用这个
bin\x64\Debug\appconfig.json       ← 开发调试用这个
```

推荐用脚本按名称合并，只动 `"Comm"` 节点，保留 `Algorithm / Flows / System / Ui`：

```bat
:: 0) 先关闭 VisionPlatform，避免退出时把文件覆盖回去
:: 1) 看现有流程的 Id / 名称
python tools\merge_comm_config.py --target bin\x64\Release\appconfig.json --list-flows

:: 2) 预览：把示例里的 F1/F2 映射到你实际的两条流程
python tools\merge_comm_config.py --target bin\x64\Release\appconfig.json ^
  --flow-map "F1=流程 1,F2=流程 2"

:: 3) 确认无误后写盘（自动生成 appconfig.json.bak-时间戳）
python tools\merge_comm_config.py --target bin\x64\Release\appconfig.json ^
  --flow-map "F1=流程 1,F2=流程 2" --apply
```

说明：

- 默认 **dry-run**，只打印将要新增/跳过的条目，不写文件；
- 同名条目默认**保留现有**，加 `--overwrite` 才会用示例覆盖；
- `--flow-map` 会同时改写任务里的 `Flows`、`StartFlow` 动作目标、`FlowBindings.Flow`；
- 映射值用流程 **Id 或名称**都可以；名称有空格时整段加引号；
- 合并后重启软件，在「通讯」和「点位/任务…」里检查端点 `SIM-PLC` 是否监听、任务是否启用。

也可以用界面手工建：通讯 → 「点位/任务…」→ 按 §3 逐项新增。示例 JSON 只作为对照，
**不要**把整个示例文件覆盖到 `appconfig.json`，否则会丢掉现有流程与系统设置。
