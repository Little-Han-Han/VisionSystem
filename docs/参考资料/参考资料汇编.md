### 1.1 Shape Context —— Belongie, Malik, Puzicha（NIPS 2000）

**原理**（2~4 行）
核心思想：「一个点的形状，就是其他点相对它排布的直方图」。设采样轮廓点 `P={p_1..p_N}`，对点 `p_i` 统计所有其他点相对它的偏移向量 `(x_j−x_i, y_j−y_i)`，按**对数极坐标**分箱：半径 `r_k = λ·(e^{k·b_r} − 1)`（λ 为标度，常取 0.1、`b_r`≈5 bins/decade），角度均分 `b_θ` 个扇区（常取 12）→ 直方图 `h_i(k)`，既是局部描述子又含蓄整体形状。不变性：平移只统计相对坐标天然不变；缩放所有距离先除以标度 λ（论文用**中位距离**，抗离群比均值更稳）；旋转角度一律相对**该点切向角**来量；遮挡用 `log(距离)` 分箱、远处点权重小，被遮一段时远点仍能找到对应，鲁棒性强于欧氏分箱。

**落地管线要点**
- `Canny`/轮廓提取 → 密集边缘像素 → 均匀采样 `N≈200~800` 点（不需角点、曲率极值等关键点）。
- 每个采样点对所有其他点求相对偏移 → log-polar 分箱 → 归一化直方图 `h_i(bins)`。
- 对应代价 `C = Σ_i [ C_S(p_i, q_β(i)) + β·C_A(p_i, q_β(i)) ]`；`C_S` 为两直方图 χ² 距离 `= ½ Σ (h_i(k)−ĥ_j(k))² / (h_i(k)+ĥ_j(k))`；`C_A` 为切向角度之差（局部外观项）。
- 求使 `C` 最小的 `β(·)` → 二分图最小权匹配：精确解 Hungarian `O(N³)`，实时场景退化为「按 `h_i` 最近邻取对应」贪心 `O(N²)`。
- 由对应点对拟合变换 → 相似度分数与位姿。数据结构：直方图 `vector<float>[N][b_r*b_θ]`（≈800×60 维浮点）+ `N×N` 代价表。

**与本项目 `algo_shape.cpp` 的关系**
- 相同骨架：都是「采样轮廓点 + 每点带一个**局部方向属性**」，再用对应/一致性求相似度。
- 关键取舍：Shape Context 走**直方图 + 全局对应搜索**（`O(N³)` 匈牙利），为识别/检索牺牲速度；本项目走**固定模板 + 位姿网格扫描 + 平均余弦相似度**，工业定位要的是**精确位姿 (x,y,θ,s)** 而不是「像不像」。
- 可借鉴：① 论文「中位距离」定标度 → 本项目缩放搜索靠显式 scale 网格，可改成「模板特征点相对中心的径向分布」辅助定标、减少无效 scale；② 分箱直方图是整数统计，可直接用 SSE 的 `_mm_add_epi` 累加，比浮点点积更省（代价是精度损失）；③ 遮挡下「远点仍可对应」→ 按点分「可靠/可疑」两档。

**来源**：*Shape Context: A New Descriptor for Shape Matching and Object Recognition*，Belongie/Malik/Puzicha，NIPS 2000, pp.831-837；姊妹篇 *Matching with Shape Contexts*（CBAIVL 2000）。PDF `https://vision.ucsd.edu/sites/default/files/publications/pdfs/Matching%20with%20Shape%20Contexts.pdf`；摘要页 `https://mlanthology.org/neurips/2000/belongie2000neurips-shape`。

### 1.2 HALCON shape-based matching（MVTec）—— 工业基准

**原理**（2~4 行）
一句话：**用「边缘点的梯度方向」而不是灰度值做匹配**，光照整体明暗、对比度变化对结果几乎无影响。设模板边缘点集 `E_T={(x_i,y_i,θ_i,w_i)}`（θ 梯度法线方向，w 边缘强度权重），搜索图 `E_S`，求位姿 `(Δx,Δy,φ,s)` 使方向一致性最大：`score = Σ_i w_i·cos( θ_image(x_i,y_i) − (θ_template_i+φ) − φ_scale(s) ) / 参与点权重和`。官方表述是「**归一化后的交叉积之和**」：两图案完全一样 `score = 1`；允许丢弃最多 x% 模板点（`MinScore`/occlusion 容忍）→ score 相应下降；在用户给定姿态范围内总选 score 最高的匹配。

**落地管线要点**
- 训练（`create_shape_model`）：手工/先验指定 ROI（两图都完整包含）→ `Canny`/`Sobel` 抽边缘 → 每点记三元组（相对 ROI 中心位置、单位梯度方向、强度权重）→ 生成多分辨率金字塔（`NumPyramidsLevels`，每层按 `ReduceMode` 抽稀：点抽稀 + 图像降采样）。
- 搜索（`find_shape_model`）：整图（受限 ROI）算一次梯度场 gx/gy（8bit/`CV_32F`），各层下采样复用 → 姿态枚举 `for φ step / for s step`，当前位姿下每个模板点的绝对采样位置**一次算好、所有位置复用**（关键）→ 最粗层全图跳步扫取局部最优、留 Top-K → 逐层向下只在上一层邻域（位置 ±n、角度/缩放 ±1 步）精化 → 最细层亚像素 + 亚角度/亚缩放精化（双线性插值梯度场）→ NMS 输出 `(row,col,angle,score)`。
- 三条决定性能的技巧：**位姿预计算**（每个 `(φ,s)` 只算一次「旋转缩放后的采样偏移 + 旋转后方向单位向量」，把大量 sin/cos 提到外层）；**金字塔**（粗层定位细层精化，搜索代价 `O(1/f²)`）；**提前终止**（① 理论上界：剩余点全满分也达不到阈值就放弃；② 贪婪启发 greediness：已评估点平均分 `< 阈值×greediness` 就放弃）。

**与本项目 `algo_shape.cpp` 的关系（几乎同构）**

| HALCON | 本项目 `algo_shape.cpp` | 对应位置 |
|---|---|---|
| Canny/Sobel 抽边缘点 | `Canny(patch, edges, contrast, 2.5·contrast, 3, true)` + `Sobel` `CV_32F` | `TrainCore` |
| 每点 (位置, 方向, 权重) | `shape.pts[]` + `shape.dir[]`（单位向量） | `ShapeModel` |
| 点重要性排序 | 按梯度幅值 `mag` 降序 `std::sort` | `TrainCore` |
| ReduceMode 抽稀 | 网格去重（同格只留最强点）`cell = ceil(min_feature_dist)` | `TrainCore` |
| 金字塔模型 | `pyrDown` 层级，层数由「最粗层模板 ≥8px 且图像 ≥32px」约束 | `FindShapeModel` |
| 姿态枚举 + 预计算 | `BuildPose(角度,缩放)` 产出 `{ox,oy,rx,ry}`，循环顺序改为**姿态在外、位置在内** | `FindShapeModel` 粗扫 |
| Top-K 候选逐层精化 | 最粗层全扫取 `bestScore[]`，逐层 ±1/±2 步邻域精化 | 精化循环 |
| 亚像素 | 最细层双线性采样 + 角度/缩放联合精化各 ±1 搜索步长分 8 档 | `refine` 段 |
| greediness | `param.greediness`（默认 0.9）+ 理论上界双重提前终止 | `ScorePose` |
| MinScore 遮挡容忍 | 当前是**所有点等权求平均余弦**，没有 per-point 丢弃 | 注意：见 1.8 |
| OpenMP / SIMD | `omp parallel for schedule(dynamic,512)` + SSE2 四路向量化 | `ScorePose` |

可借鉴三点：① `determine_shape_model_params` 的「自动估计对比度/层数」——本项目 `numContrast` 是手工值，可补自动档（Canny 默认高低的 Otsu 式估计）；② 允许**丢弃低分点**后再归一化（occlusion 模型），比「全部点进分母」更抗遮挡；③ 输出模板轮廓（`get_shape_model_contour`）——本项目已导出 `va_get_shape_model_points`（位置+方向），可直接拿去画轮廓。

**来源**：MVTec HALCON 参考手册 `create_shape_model` / `find_shape_model` / `determine_shape_model_params`（商用、文档公开）；ESA 技术报告 *High Accuracy Matching of Planetary Images* §2.1 `https://sci.esa.int/c/portal/doc.cfm?fobjectid=40238`（明确引用 HALCON 形状匹配与对应专利）；中文原理综述 `https://devpress.csdn.net/v1/article/detail/151802492`。

### 1.3 OpenCV `cv::matchShapes` / `cv::HuMoments` —— 全局不变矩

**原理**（2~4 行）
用**图像的归一化中心矩**构造 7 个对平移/旋转/缩放（及镜像）不变的标量：`ν_ji = m_ji / m_00^{(j+i)/2+1}`；`hu[0]=ν20+ν02`；`hu[1]=(ν20−ν02)²+4ν11²`；`hu[2]=(ν30−3ν12)²+(3ν21−ν03)²`；`hu[3]=(ν30+ν12)²+(ν21+ν03)²`；`hu[4..6]` 为三次混合项。文档原话：这些不变性**建立在「无限分辨率」假设上**，对栅格化图像只是近似成立。

**落地管线要点**
- `findContours` 取轮廓（或直接吃灰度图）→ `moments` → `HuMoments()` → 7 个 double。
- 为让「小但形状相似」不被数值压倒，先取 `mi = sign(hi)·log10|hi|`。
- 距离三种 mode：`I1=Σ|1/mA_i − 1/mB_i|`、`I2=Σ|mA_i − mB_i|`、`I3=Σ|mA_i − mB_i| / |mA_i|`，本质都是 Hu 矩空间 L1 距离，区别只在是否取倒数/做归一化。
- 返回 `0~∞` 的 dissimilarity（越小越像）。

**与本项目 `algo_shape.cpp` 的关系**
- 优点：`O(N)` 一次算完、速度极快，**天然支持任意角度/缩放/平移**。
- 致命缺点：只给一个「像不像」标量、**给不出位姿**（要位姿就得全图代价图搜索），且对**局部遮挡/部分缺陷**极敏感（一个角缺了高阶矩全变）。
- 本项目定位：可作「有没有这个形状」的快速预筛（金字塔粗层之前先过一遍 Hu 矩），或「缺陷检测：形状整体是否还正常」；不适合做定位主算法。

**来源**：OpenCV 文档 `group__imgproc__shape` `https://docs.opencv.org/4.x/d3/dc0/group__imgproc__shape.html`；源码 `modules/imgproc/src/matchcontours.cpp`。

### 1.4 OpenCV contrib `modules/shape` —— 开源版 Shape Context / Hausdorff

**原理与实现**（2~4 行）
把 §1.1 的 Shape Context **工程化**，统一接口 `ShapeDistanceExtractor::computeDistance(contour1, contour2) -> float`。

| 类 | 原理 | 实现要点 |
|---|---|---|
| `ShapeContextDistanceExtractor` | log-polar 直方图 + χ²/EMD 代价；支持切向角、形变弯曲能 | 参数 `setAngularBins` / `setRadialBins` / `setInnerRadius` / `setOuterRadius` / `setShapeContextWeight` / `setImageAppearanceWeight` / `setBendingEnergyWeight` / `setTransformAlgorithm` |
| `HausdorffDistanceExtractor` | 点集 Hausdorff 距离（对称版 + rank proportion 抗噪） | 两套代价矩阵，KDTree 加速近邻查询 |
| `ThinPlateSplineShapeTransformer` | TPS 薄板样条形变 | `setRegularizationParameter`；用于**可形变匹配**（柔性件） |
| `AffineTransformer` / `estimateTransformation` | 位姿估计 | 由对应点对拟合仿射（§1.1 第 5 步） |
| `HistogramCostExtractor` 系列 | 直方图代价 Norm / EMD / Chi / EMDL1 | 影响 `C_S` 项的计算方式 |

**与本项目 `algo_shape.cpp` 的关系**
- 这是**最接近本项目思路的开源实现**（同样是「轮廓点 + 局部方向/直方图属性 + 距离」），可直接当参考实现翻源码对照。
- 但它做的是「形状相似度/检索」：`computeDistance` 只吐一个距离、位姿靠 `estimateTransformation` 反解；本项目要「给定姿态范围求最优位姿」，这是**搜索问题**不是**比较问题**——二者分水岭。
- 可借鉴：`Hausdorff` 的 rank-proportion 抗噪（用「前 k% 近邻的平均距离」代替最坏值）升级 `ScorePose`：现在「所有模板点平均余弦」改成「取最差 q% 点做截断平均（trimmed mean）」，遮挡鲁棒性会明显变好。

**来源**：OpenCV `modules/shape` "Shape Distance and Matching" `https://docs.opencv.org/3.0-beta/modules/shape/doc/shape.html`；示例 `modules/shape/samples/shape_example.cpp`（读 `../data/shape_sample` 一对图，输出最近邻排序）。

### 1.5 OpenCV `cv::matchTemplate`（TM_CCOEFF_NORMED）—— 灰度 NCC

**原理**（2~4 行）
滑动窗口求相似度，6 种方法中最常用归一化互相关：`R(x,y) = Σ_{x',y'}( T'(x',y')·I'(x+x',y+y') ) / sqrt( ΣT'² · ΣI'² )`，其中 `T'=T−mean(T)`、`I'=I(窗口)−mean(I(窗口))`。

**落地管线要点（速度是它真正的价值）**
- `matchTemplate` 统一先把「模板卷积图」算好，几种 method 共享这部分。
- `TM_CCOEFF_NORMED` 需 `ΣI` 与 `ΣI²` → 用积分图 `integral` 一次扫出，避免每位置重算。
- 大模板（>某阈值）走 `crossCorr` / DFT（`mulSpectrums` 取共轭即互相关）；小模板走 `hal::` 通用 SIMD 后端（SSE/AVX/NEON）。
- `UMat` + OpenCL 走 `match_template.cl`（CCORR / SQDIFF / CCOEFF 宏开关）；`minMaxLoc` 取全局极值 → 最多只有一个平移位姿。

**与本项目 `algo_shape.cpp` 的关系**
- 本项目 `va_match`（`va_match_template` / `va_match_template_ex`）就是它：8bit 灰度 + `TM_CCOEFF_NORMED`。旧接口只支持平移；`_ex` 版本已支持角度 / 缩放 / 金字塔 / 多目标，且对外分数由「去掉旋转 padding 的有效像素」重算（见 `docs/算法/算法更新记录.md`）。
- 为什么另做形状匹配：`matchTemplate` 在旋转/缩放时**结果会崩**（模板与窗口错位，归一化后分数反而可能接近 1，产生假阳性）。
- 可借鉴：积分图这招对本项目也适用——评分需「该位置邻域内梯度场统计」，若改成**用积分图预计算局部 `Σg`、`Σg²`、`Σ|g|`**，可省掉双线性采样里的部分加法，且对平滑区（非边缘区）更稳。

**来源**：OpenCV Template Matching 教程 `https://docs.opencv.org/3.0.0/de/da9/tutorial_template_matching.html`；源码 `modules/imgproc/src/templmatch.cpp`；OpenCL `modules/imgproc/src/opencl/match_template.cl`。

### 1.6 ORB（Rublee, Rabaud, Konolige, Bradski，ICCV 2011）—— 对照组

**原理**（2~4 行）
FAST 角点 + 旋转 BRIEF 二进制描述子：① `oFAST`：金字塔各层跑 FAST 角点 → Harris 响应排序取前 N → 强度质心定方向 `θ = atan2(m01, m10)`，`m_pq = Σ x^p y^q I(x,y)`（patch 内）；② `rBRIEF`：对 n 个测试点对 `(a_i,b_i)` 做二值比较 `I(a)<I(b)` → 256 bit 串（32 字节），旋转时所有点对先绕质心转 θ（量化成 30 个角度档、预制 LUT），去相关靠离线贪心搜索「方差大（均值≈0.5）且互不相关」的测试对；③ 匹配：汉明距离 `popcount(x⊕y)`（几条机器指令）+ ratio test（0.7~0.8）+ RANSAC。

**为什么不适合本项目场景（重要结论）**

| 维度 | ORB / 点特征法 | 边缘轮廓形状匹配（本项目） |
|---|---|---|
| 前提 | 目标要有**丰富纹理**（角点足够） | 只要**轮廓清晰**即可 |
| 工业零件（无纹理/金属面） | 否：常凑不出 8~10 个可靠角点 | 是：边缘天然存在 |
| 亚像素精度 | 靠角点定位，受纹理质量制约 | 靠梯度场插值，可达 0.1 px 级 |
| 输出 | 一堆 2D 点对应 → 需拟合 | 直接输出 `(x, y, θ, s)` |
| 视角变化 | 是：天然支持（单应/平面） | 否：只支持平面内旋转缩放 |

结论：本项目（工业零件平面定位）走边缘轮廓路线是正确选择；ORB 只在「目标有明显纹理且视角会变」时才值得考虑。

**来源**：*ORB: an efficient alternative to SIFT or SURF*，ICCV 2011 `https://sites.cc.gatech.edu/classes/AY2024/cs4475_summer/images/ORB_an_efficient_alternative_to_SIFT_or_SURF.pdf`；OpenCV `features2d` 文档。

### 1.7 实现踩坑要点（`algo_shape.cpp` 工程附注）

> 出处说明：本节的 `kDirBins`、`cv::phase`、诊断开关、 Bench-D 门限等均为项目内 `docs/遗留问题.md` / `algo_shape.cpp` 的真实实现记录，不属于上述两份论文/界面资料，作为「落地管线要点」的补充单列，以免与论文结论混淆。

**背景**：内层原本「逐姿态 × 逐点算 `atan2` 再取余弦」，360 姿态就是 360 遍三角函数，是全角度慢的根因（BENCH-D 1280×960 全角度 360 姿态：Debug 790.0ms / Release 162.1ms）。改法保留金字塔/候选/NMS/亚像素、对外 API 不变。

| 要点 | 具体实现 |
|---|---|
| 梯度方向量化查表 `kDirBins=32` | 32 档（最坏 5.6° 量化误差，cos 误差 ≤0.005）。图像每个像素的梯度方向一次性 `cv::phase` 向量化算好存 1 字节；模板各层也存一份 |
| 旋转 = 档位整体平移 | 纯旋转下「模板点方向」与「图像点方向」夹角 = `(图像档 − 模板档)` 绕圈相减，故某姿态模板档位 = 基准档位整体 `+round(angle·32/360)`；姿态预计算阶段一次做完，**内层不再有任何三角函数** |
| cos 响应表 `g_dirCos` | 32×32 = 1024 float = 4KB，常驻 L1；内层变成「读 1 字节 + 查表 + 累加」 |
| `cv::integral` 边缘支持度剪枝 | 同趟生成「有梯度」mask 再过 `cv::integral`；搜索位置按模板外接圆矩形查积分图，`cnt == 0` 直接跳过该位置——这是**严格上界**（模板落这里一分也拿不到），不是启发式 |
| 只在粗层启用 + `kFastPathMinWork` 工作量门槛 | `useFast = (L0 >= 1) && (coarseWork >= kFastPathMinWork) && !ForcePrecise()`；粗层降采样（1px 误差可接受），最细层仍走精确双线性 + 精确 `atan2` 保亚像素。`coarseWork < 400000` 时门槛把查表关掉走原精确路径，否则建方向图 + 积分图的一次性开销在小搜索摊不回（实测把 A 从 38.5 拖到 41.8） |
| 最细层必须精确 `atan2` + 双线性 | 粗层 5.6° 量化误差由最细层精确 `atan2` + 双线性精修兜住；**细层不要也换成查表**，否则引入 ≤0.01 的系统性得分偏差（S1） |
| `VA_SHAPE_DEBUG` / `VA_SHAPE_PRECISE` 诊断开关 | `VA_SHAPE_DEBUG=1` 打印 `levels/L0/nPos/keep/nPoses/fast/cands/build/coarse/edgePx` 与前 6 名候选；`VA_SHAPE_PRECISE=1` 强制走精确路径做 A/B 对照；靠环境变量、生产默认全关（S2） |
| Bench-D 600ms 门限 | `BENCH-D 耗时` 门限 **1500ms → 600ms**。1500 是最初目标值，优化后 Debug 154ms / Release 24ms；若 `useFast` 判据或 `kFastPathMinWork` 改坏，耗时掉回 800ms 级，1500 门限照样 PASS、回归静默溜走。600ms 仍留 ~4× 余量（Debug）但能抓住「查表路径整体没生效」；A/B/C 三条仍保留原始目标值 |

**真实踩过的坑（已修，记录以防再犯）**

| 现象 | 根因 |
|---|---|
| 改完**全部 0 命中**，最佳候选落在图像边缘且得分约 0.4 | `cv::phase(gx, gy, ang, false)` 返回**弧度**（第 4 参 `angleInDegrees` 要传 `true`），代码按「度→档位」换算 → 所有像素落到档位 0 |
| 小规模搜索（A）反而慢 2.7ms | 方向图 + 积分图是每帧一次性开销，与 `nPos × nPoses` 无关；用 `kFastPathMinWork` 门槛按工作量分流 |

**效果数据**：改动后 B 旋转 17° 42.0 / 6.1ms（−38% / −46%）、C 旋转+缩放 66.7 / 13.4ms（−67% / −67%）、D 全角度 360 姿态 154.1 / 23.9ms（−80% 5.1× / −85% 6.8×）；精度未退化，原 6 条断言全绿且数值一致（B 角度误差 0.00°、C 缩放误差 0.000、D 角度误差 0.00°，得分仍 0.981 / 0.985），补 BENCH-I（190 灰 + sigma=8 噪声 seed 固定）得分 0.992 / 位置误差 0.707px、BENCH-J（同前 + 旋转 17°）得分 0.978 / 角度误差 0.25°；SmokeUi 650 / SmokeAlgo 200（Debug + Release 全绿）。

### 1.8 选型对照、数据流与小结

| 方法 | 平移 | 旋转 | 缩放 | 局部遮挡 | 光照变化 | 速度 | 工程复杂度 |
|---|---|---|---|---|---|---|---|
| 灰度 NCC（1.5） | 是 | 否 | 否 | 部分 | 否 | 快 | 低 |
| Hu 矩（1.3） | 是 | 是 | 是 | 否 | 部分 | 极快 | 低（仅分数） |
| Shape Context（1.1 / 1.4） | 是 | 是 | 是 | 是 | 是 | 慢（`O(N³)` 匈牙利） | 高 |
| **边缘梯度 + 位姿扫（1.2 ← 本项目）** | 是 | 是 | 是 | 是 | 是 | 中~快 | 中 |

`algo_shape.cpp` 数据流：
```
训练  Bitmap(任意格式) → GrayInput(8bpp 灰度, pinned)
      → Canny(contrast, 2.5×, L2) 抽边缘 → Sobel 求 gx/gy 降序
      → 网格去重(cell=ceil(min_feature_dist)) → ShapeModel{pts, dir, w, h}
      → va_create_shape_model_ex / va_get_shape_model_points（可导出画特征图层）
搜索  Bitmap → GrayInput → pyrDown 建 L0..Lk 层梯度场
      → 最粗层：姿态(φ,s) 在外、位置在内；BuildPose 预计算 {ox,oy,rx,ry}
      → ScorePose：平均余弦相似度 + 理论上界/贪婪双重提前终止（SSE2 四路）
      → bestScore[] 取 Top-K → 逐层邻域精化 → 最细层亚像素（角度+缩放 8 档）
      → NMS 去重 → VA_ShapeMatch{cx, cy, angle, scale, score, w, h}
```

后续最值得借鉴三件事（优先级从高到低）：① 遮挡容差（对应 HALCON `MinScore`）——现在是「所有模板点等权进分母」，被遮一半就掉分，建议对「余弦 < 局部阈值」的点计 out-of-figure、只参与分子不参与分母，并输出 `score` 与 `used_ratio`；② 截尾平均（对应 `modules/shape` 的 rank / Hausdorff）——用「最差 q% 点截断」替代纯平均；③ 自动训练参数——模仿 `determine_shape_model_params`：用 Otsu/梯度直方图自动估 Canny 对比度，特征点数自动设 100~600。

一句话小结：要「有没有这个形状」（分类/缺陷判定）→ Hu 矩（1.3）；要「形状像不像，给相似度」（检索/聚类）→ Shape Context（1.1 / 1.4）；要「刚体零件在哪、转了多少度、放大了多少倍」（工业定位）→ **边缘梯度 + 金字塔 + 位姿扫描**（1.2，`VisionAlgo.Native` 现实现）；目标有纹理、视角还会变 → ORB / SIFT（1.6）。
